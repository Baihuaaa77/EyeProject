# feature:services

三项协议、状态、问卷模型、状态机、计算规则、注视监督和语音指令解析已迁到 `shared/screening/src/commonMain/kotlin`。安卓 ViewModel 仅连接 `AndroidScreeningPlatform`；修改规则必须修改共享目录。iOS 工程与当前验收边界见 `docs/iOS适配与双端构建.md`。

> 眼病症自检服务集合：干眼 / 老视 / 斜视三项测试，流程对齐《智能眼科-整合9.18》（对照表见 `docs/三病种流程对齐-2026-10-11.md`）。

## 当前视觉

以 `DESIGN.md` 为准：顶部标题与浮雕账户按钮、方法示范主卡、干眼 / 眼位 / 老视 / 色觉四项双列浮雕入口。原回调保留；测试内示范自动播放，服务页示范支持点击切换，移除动画时显示关键帧。测试准备、问卷、测距、结果页共享同一组主题与控件。测试刺激与计时逻辑保持原有实现。

按用户 2026-11-09 的反馈，四项自测图标分别为绿、紫、橙、玫红；大字号时方向按键采用设计系统的紧凑尺寸，视标物理尺寸保持原样。

标题统一采用放大后的设计令牌：页标题 28、分区 22、卡片与示范标题 20。

## 爱科数字人方法演示

十四种方法演示统一使用爱科照片分镜（自然注视、闭眼、遮左/右眼、协助者遮左/右眼及移开遮盖），
素材与提示词位于 `shared/guide/`，Android / iOS 直接打包同一份透明 PNG。图片等比适配，不镜像、不裁切头顶与手势。
`GuideDemo.kt` 负责分镜、时序与步骤文字；`EyechoGuideStage.kt` 展示人物及原生手机、视标、移动目标示意。
现阶段采用图片分镜，尚未接入生成视频；步骤高亮、准备确认、减弱动态效果仍保留。

- 近视力（NEAR）先遮左眼，再移开并换遮右眼；交替遮盖按测前选择切换自行/协助者图片，不混用。
- 交替遮盖教学循环为 12 秒：遮右 2 秒、双眼 2 秒、遮左 2 秒、双眼 2 秒，最后每眼 1 秒交替两轮。
- 眨眼用睁眼/闭眼图片短暂切换；持续睁眼段不插入眨眼分镜。
- 手机移近/移远、方向作答和移动目标仍有原生简图与文字讲解，正式视标、采样、计时与评分保持原样。
- `GuideMotionPreviewTest` 输出三组遮眼完整循环及十四种场景深浅关键帧，目录为 `build/reports/guide-motion-frames/`。

系统减少动画时停在关键帧并显示全部步骤；测试内不提供暂停演示按钮。回看预览来自真实 Compose，不参与测量或计时。

## 职责

- 服务页以双列浮雕卡片列出四项自测入口（`ServiceTile`）
- 干眼自测：选择被测者 → 视标练习 → 60 秒自然眨眼 + 紧接 20 秒持续睁眼的功能性连续视力测试，同步记录眨眼
- 提供通用的「摄像头预览 + 眼部关键点标注」检测界面组件

### 干眼测试（DryEyeTestViewModel）

- 流程：选择被测者（原文问卷全部条目在「我的」资料里）→ 准备（提示最佳矫正眼镜、40±5 cm 门禁）→ 练习说明 → 12 秒练习（0.3 起，错/超时放大一档、连对两次缩小一档）→ 正式说明 → 3 秒倒计时 → 自然眨眼 60 秒 → **不停顿**转入持续睁眼 20 秒 → 结果。
- 正式两段全程辨认视标：每题最多 2 秒、超时记错，作答后 300 ms 出下一题，按实测距离换算视标像素，超出本机像素能力自动封顶。
- 眨眼走事件队列（`ConcurrentLinkedQueue`），不会因轮询丢失；测试中双眼不可见 > 1.5 秒或距离超出 30–50 cm > 3 秒判为中断（结果标记无效）。
- 「延长测试」「休息后复测」的可用条件由共享状态 `canExtend` / `canRestRetest` 判定，引擎也据此拒绝无效调用；正式测试开始时清零上一段的跟踪丢失计时与像素封顶标记。
- 结果：有效性 + 低/中/高风险 + 主要异常指标（眨眼 10–16 次/分、睁眼阶段最长持续睁眼 ≥ 10 秒、视觉维持率、视力下降时间）+ 就医建议；临界时可「延长测试（自然眨眼 3 分钟）」，可「闭眼休息 1 分钟后复测」并与上一次对比。原始逐题数据写入 `dryeye_<时间>.json`。
- 使用 CameraController 帧流；进入后台会中断本次测试，可从设置菜单停止。

### 记录详情与数据可靠性（2026-10-20）

- 三病种新记录保存 `report` 展示快照（结论、建议、证据、明细与版本），由 `LocalRecordCatalog` 同时提供两端历史查看与文字报告导出；旧记录读取已有数据，不使用新规则重新评分。
- 干眼 `DryEyeReliability` 只补充描述：完成情况、有效帧/距离/头姿比例、分析帧率、每约 500 ms 距离样本的均值/标准差与无读数比例、分阶段作答和超时数量、连续未作答、像素限制。结果页展示可展开的可靠性说明，明细放在「本次数据」；正式阶段保存 `distanceSamples`，没有数据时显示未记录。
- 低帧率、持续睁眼段眨眼、语音识别延迟、前摄估距限制会如实说明；不新增风险阈值，不改变 `dryeye-9.18-rules-2` 的评分与质量不足拒判规则。

### 交互：语音作答与距离反馈

- `TestFeedbackEffect` 接入共用 `ScreeningFeedbackSession`：开始、阶段切换、倒计时、有效作答／跳过、标定点切换、校准失败、遮盖动作及保持结束、完成时提供短音与轻触觉。作答不区分对错，完成音也不区分风险结论。固定距离持续异常 800 ms 后提醒一次；短暂丢脸不重置同一区间的提醒，恢复合适 800 ms 后轻提示一次，再次告警至少间隔 5 秒；连续追踪与注视闪烁不逐帧反馈。
- 音效／震动默认开启，独立开关集中在系统设置并保存；菜单可点「试一下反馈」独立验证输出，普通测试事件在菜单、权限弹窗、后台期间丢弃，返回不补播。安卓 SoundPool 使用媒体音量，静音铃声和关闭系统按键音不再阻断测试音效；Vibrator 使用交互内容的媒体震动用途并分级：作答／节拍最轻、阶段切换次之、距离提醒与重试两下、完成渐强三下；支持触觉原语的设备用组合效果，Android 10+ 回落系统预定义效果，Android 8–9 使用 25 ms 短脉冲兼容，不依赖 View 的触摸反馈调用，也不绕过系统勿扰限制。首次音效载入最多等待 300 ms，关闭页面或切后台即丢弃。音量按事件分级（高频作答 0.5、提醒与完成 0.7）。iOS 使用 UI 系统音效，触觉按同一分级使用选择／冲击／通知反馈生成器并预热。倒计时 3、2、1 只用节拍音，归零进入任务时才播开始音。音效为 `shared/feedback/res/raw` 的同一套原创 WAV，生成脚本在 `scripts/generate_feedback_sounds.py`（柔和钟片音色、余弦起音、相邻音符交叠，时长不超过原尾音预算）。短音不打断 TTS，麦克风按音长加尾音暂停 110–320 ms，旧识别会话丢弃后恢复；计时、视标和评分不等待反馈。

- 测试开始后（干眼从练习说明起、老视/斜视从首个任务引导起，至结果页前）顶栏下显示整体进度细条与「剩余约 N 分钟/秒」。进度与剩余时间由共享 `TestProgress`（`dryEyeProgress` / `screeningProgress`）计算：固定时长阶段按实际倒计时推进，视力阶梯、移近、遮盖等可变阶段按 `TestProgressEstimate` 经验时长估算并封顶，不会越过下一阶段起点；引导页停留时进度不动。仅作提示，不参与计时与评分。
- `TestSessionLayout` 在进行中的任务里居中呈现内容，保留小屏滚动；顶栏仅保留返回、测试名和实心齿轮。需要固定距离的任务在顶栏下常驻距离横幅，合适时也保留标题、距离和小标尺，状态变化不挤动测试舞台。移近法和遮盖仍不提示固定距离。移除重复目的说明与实时采集计数；校准目标仍上报实际绘制位置，视标物理尺寸、计时与质量门控不变。
- 进行中的任务若内容放得下，`TestSessionLayout` 把内容区剩余高度交给舞台中唯一的可伸展元素（白色刺激区、注视/追踪画布、移近视标区，经 `rememberStageExtra()` 登记），卡片铺满到底部、视标居中、作答键靠下，不再上下大片留白；放不下时保持原高度并可滚动。注视校准与追踪卡片结构相同，伸展后仍同高。iOS 用 `ViewThatFits` + `stageHeight()` 实现同样效果。
- `TestStageCard` 为测试区域增加主色细框和轻阴影；白色刺激区圆角收边，E 周围为固定留白的圆框，等待下一题时变淡、出题时恢复。方向键为绘制箭头的圆形按钮（按下轻缩、加深底色），「跳过」为与方向键同尺寸的浅底圆键。刺激区固定白底，其上视标环与校准点取亮色主色令牌（`StageAccent`），深色主题下仍有足够对比。`TestNotice` 让任务中的质量提醒以浅色胶囊淡入展开、收起消失。干眼倒计时与闭眼休息使用圆环计时，数字缩放淡入；注视校准点换位时外圈收拢提示，上报位置不变。系统移除动画时以上动效静止。装饰不增加说明文字，不缩放视标或改变作答门控；iOS 同步呈现。
- 齿轮打开「系统设置」，三项测试共用并持久化语音播报、语音作答偏好，以及音效音量、震动强度、播报音量、播报语速四个滑块（默认即原有分级与常速）；非紧急播报等当前这句说完再开口，距离提醒仍即时打断。选人页可「暂不选择，直接测试」（记录 `profileSkipped`）；麦克风授权、识别状态、测量详情与干眼停止操作集中在菜单中。测试界面不放语音开关或常驻语音提示栏。

## 注意事项

- 本模块与 `core:camera` 的集成方式是「自带预览绑定」：`FaceLandmarkerAnalyzer` 共享单例引擎（回调列表机制），但相机生命周期由本模块 ViewModel 管理
- 干眼测试的计时/相位状态在 ViewModel 内协程驱动，`onCleared` 时务必停相机
- 老视流程（专家 2026-11-02）：选择被测者 → 戴镜问卷（是否知道有近视远视散光、平时怎么用眼镜〔同一副看远看近时追问镜片分区〕、看远是否需要眼镜、这次怎么戴镜）→ 分流 A1 远用矫正 / A2 裸眼 / B 现有近用眼镜 / C 限制性筛查（`PresbyopiaIntake.route`，未选成员按 C）→ 戴镜确认 → 40 cm 近视力（右/左/双）→ 多距离视力 67/50/33 cm →（仅 A1 / A2）单眼移近法右、左眼各 3 次（≥45 cm 起，推荐 1–2 cm/秒，> 3 cm/秒提示慢一点，确认时 > 5 cm/秒本次无效；视标物理尺寸固定；首次持续模糊）→ 远近切换（可选，可跳过；先在 50、25 cm 各看清一次，近端看不清记为未达到测试条件；60 秒记正确完整循环 50→25→50、错误次数与未完成原因，不设阈值）→ 结果
- 老视结果：A1 / A2 每眼三次调节幅度取算术平均（保留每次原始值与标准差），按较差眼与同龄比较，初步 ADD = 2.5 D − 调节幅度 / 2（按 0.25 D 取整，仅供参考）；B、C 不做标准调节幅度也不估算 ADD。结果页「换一种戴镜方式再测」保留前几题只重选本次戴镜状态，各次独立记录；与上次对比只比同一路径、同一戴镜状态的记录
- 斜视流程：选择被测者 → 33±5 cm → 卡通闪烁注视 12 秒（目标紧贴顶栏下方）→ 看远（协助者点「已在看 6 米外的目标，开始」后计时 10 秒）→ 交替遮盖 9 个动作（相机识别动作首帧并自动开始保持计时，无需点屏幕）→ 追踪 22 秒（±10° 按实测距离换算，屏幕不足时缩小并记录）→ 结果
- 看远（专家 2026-10-29 建议，替代「缩小视标模拟 2 m」）：手机留在眼前约 33 cm、略低于视线，受试者越过手机注视 6 米外的目标 10 秒（前 1.5 秒不计），前置相机同时测双眼映光，HDE/VDE 与看近同一算法和判定线（`StrabismusMeasures.far*`、证据 `far`）；看远头部俯仰门控放宽到 20°；协助者确认受试者已在看远处之前不计时、不采集（`farWaiting`）；舞台用深色避免整屏亮光映出大片反光，最后 3 秒节拍音；看远数据不足只是不评估看远，不使整次测试无效；只在看远时越线提示可能为间歇性斜视。记录 `protocolVersion` 6
