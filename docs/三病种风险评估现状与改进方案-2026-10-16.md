## 0 结论先行

1. **是的，三项测试仍是写死的阈值规则。** 判定代码分别是 `DryEyeAssessment.evaluate`（规则版本 `dryeye-9.18-rules-1`）与 `ScreeningAssessmentModel.presbyopia / strabismus`（`protocol-9.18-rules-1`）。阈值来自《整合 9.18》引用的经验值或本项目的「候选」约定，**没有一个经过本设备或临床队列验证**；输出只有 LOW / MEDIUM / HIGH / UNKNOWN 四档，没有概率、置信区间或临界带（干眼的 `borderline` 只影响建议文案）。
2. **当前规则最大的问题不是阈值「不够准」，而是测量噪声直接变成了异常。** 例如：
   - 干眼的「视觉维持率 < 0.85」只相当于平均视标下降 **0.07 logMAR，不到一档**；「下降 ≥ 2 档」只需连续两次答错。按蒙特卡洛模拟（附录 B），一个**视力完全不变**的受试者在现行阶梯规则下，约 **40%–55%** 会触发这两条中的至少一条，单凭这一条就会被判「中风险」。
   - 眨眼检测按「连续 3 帧 EAR < 0.23」判定，**依赖帧率**：按假设的闭眼时长模拟，10 fps 时只能检出约 23% 的眨眼，30 fps 约 97%。iPhone 真机记录里每分钟只记到 3 次眨眼，就是这个原因（相机分析帧率刚提到约 30 fps，修复已推送）。
   - 斜视的 Hirschberg 换算是 175.5 Δ / 虹膜直径；若 33 cm 处虹膜约 40 px，**1 px 定位误差就约等于 4.4Δ**，而高度疑似阈值是 10Δ。iPhone 记录中 2,310 帧里有 2,258 帧因「瞳孔对比度不足」被拒，光学测量 0 帧有效，斜视主判据在 iPhone 上目前完全不可用。
3. **还有结构性问题**：同源指标重复计数（两个眨眼指标来自同一个检测器，两个视力指标来自同一条阶梯轨迹）；硬切点没有不确定性（44.9 岁和 45 岁、9.9Δ 和 10.0Δ 结论不同）；常模来自文献而非本设备、本任务条件（如看屏任务本身就会抑制眨眼）；规则只用汇总特征，没用已经记录的原始序列；已经算出的多项指标（反应时、眨眼前后正确率、离焦曲线）没有进入判定。
4. **不需要临床标签就能做、且应先做的**（§6）：测量层修正（帧率门控与按时间判定眨眼、超时与答错分开、iPhone 映光改用虹膜中心参照）→ 用心理测量模型替代 VMR/下降时间 → 指标级置信区间 + 测量误差保护带 + 三向判定（明确正常 / 明确异常 / 不确定→延长或复测）→ 按来源合并证据族、按质量加权 → 内部重测研究得到 SEM，用于个人纵向变化判断 → 规则配置化 + 模拟回归测试。这些都是**底线规则本身的升级**（需升规则版本号），不违背 §5 L5「模型不能下调规则」。
5. **机器学习路线**（§7）：先表格模型（带单调约束的逻辑回归 / GBM / 可解释加性模型），再在原始序列上做时序模型；概率校准 + 保形预测做拒判；按受试者划分、跨设备外部验证；先服务端影子评分，验证通过后才把系数或树下发到设备端（KMP 共享代码执行，三端结果一致）。**所有「风险概率」「敏感度/特异度」的对外表述都必须等有金标准标签的临床数据**；现在能用机器学习做的是测量层（眨眼、瞳孔/映光定位）、常模建模和无监督预训练，其中前两项需要临床团队同意采集眼区图像或健康人对照数据（❓§9）。
6. 本文未选择任何付费服务，也不涉及健康数据出设备；LLM、托管、图像采集等仍按设计文档 §9 待决。

## 1 共同框架（现状）

```
问卷（profile） ──┐
相机帧 ─ MediaPipe 人脸/虹膜关键点 ─ 测距/头姿/EAR/映光 ─┐
视标呈现与作答 ────────────────────────────────────────┤
                                                       ▼
                         L0 质量门控（任一条不满足 → UNKNOWN「无法评估/请重测」）
                                                       ▼
                         L1 指标计算（features 映射，随记录保存）
                                                       ▼
                         L2 规则分级（计数异常项 / 判据命中 → LOW·MEDIUM·HIGH）
                                                       ▼
                         模板化结论 + 建议 + 局限说明（结果页 / JSON 记录）
```

- 等级枚举 `ScreeningRiskLevel { LOW, MEDIUM, HIGH, UNKNOWN }`；斜视显示为「未见异常 / 可疑阳性 / 高度疑似斜视 / 测试质量不佳」。UNKNOWN 不能解释为低风险——这一点做得对，应保留。
- 每份记录保存 `features`（数值表）、逐题作答、规则版本号；斜视还保存逐帧 `eyeSamples`。干眼记录**没有**保存逐帧 EAR 和距离轨迹，老视记录**没有**保存移近过程的距离—时间轨迹（只存模糊时的距离、速度和起点）。
- `backend/screening_model.py` 已按当前特征名（`dryeye-9.18-rules-1` / `protocol-9.18-rules-1`）更新（设计文档 §0 第 1 条所说的「特征版本过期」已解决）；它是标准库实现的带类别权重逻辑回归，按受试者留出 20% 做验证，输出明确标注为「未校准的研究分数」。

## 2 干眼（研究内容一）

### 2.1 测试流程与数据

| 阶段   | 内容                                        | 关键参数（`DryEyeProtocol`）                                |
| ---- | ----------------------------------------- | ----------------------------------------------------- |
| 问卷   | 年龄、性别、症状（多选）、症状频率、屏幕时长、隐形眼镜、全身病等 15 题；可跳过 | 跳过时症状按「未报告」处理                                         |
| 门禁   | 双眼可见且距离 40 ± 5 cm 才能开始                    | `TARGET_DISTANCE_CM = 40`，`DISTANCE_TOLERANCE_CM = 5` |
| 练习   | 12 秒，从 0.3 开始的阶梯                          | `PRACTICE_SECONDS = 12`；结束档位 = **基线**                 |
| 自然眨眼 | 60 秒（可延长到 180 秒），看 E 选方向                  | 每题最长 2 秒，超时记错；答后 300 ms 出下一题                          |
| 持续睁眼 | 紧接 20 秒，尽量不眨眼，继续作答                        | `OPEN_SECONDS = 20`                                   |
| 中断   | 双眼不可见 > 1.5 秒或距离超出 30–50 cm > 3 秒         | 测试标记未完成 → UNKNOWN                                     |

阶梯规则（`DryEyeStaircase`）：**连续 2 次答对缩小一档，1 次答错或超时放大一档**；档位为小数视力 0.1–1.2 共 12 档（每档约 0.1 logMAR），超出本机像素能力自动封顶。正式测试从基线档位接着走。

眨眼检测（`BlinkDetector`）：双眼平均 EAR = (‖p2−p6‖ + ‖p3−p5‖) / (2‖p1−p4‖)，**EAR < 0.23 连续 3 帧**判闭眼，回升时记一次眨眼。阈值固定，不随个人眼型调整，判定以帧数而非时间计。

### 2.2 质量门控（任一条 → UNKNOWN）

| 条件                        | 阈值                   |
| ------------------------- | -------------------- |
| 测试未完整完成                   | `completed == false` |
| 自然眨眼段有效题数                 | < 10 题               |
| 睁眼段有效题数                   | < 4 题                |
| 双眼可见的有效帧比例                | < 80%                |
| 距离在 40 ± 5 cm 内的时间        | < 70%                |
| 头部偏转（yaw 或 pitch > 15°）时间 | > 30%                |

**没有**帧率门控、眨眼检测可靠性门控、无应答（超时）比例门控。

### 2.3 指标定义

| 指标                         | 公式 / 来源                                | 判异常条件           | 阈值身份                            |
| -------------------------- | -------------------------------------- | --------------- | ------------------------------- |
| 眨眼频率                       | 自然段眨眼数 × 60 / 自然段秒数                    | < 10 或 > 16 次/分 | 原文「正常 10–16 次/分」                |
| 最长持续睁眼                     | 睁眼段（含段首到首次眨眼、末次眨眼到段尾）最大间隔              | < 10 秒          | 原文「正常眨眼间隔 > 10 秒」，本项目解释为睁眼段最长间隔 |
| 视觉维持率 VMR                  | 10^−(正式段按呈现时长加权的平均 logMAR − 基线 logMAR) | < 0.85          | **候选**，未验证                      |
| 视力下降时间                     | 睁眼段内视标比该段首题放大 ≥ 2 档的首个时刻               | 只要出现即异常         | **候选** `DECLINE_STEPS = 2`      |
| 正确率、超时数、平均反应时、眨眼前/后 2 秒正确率 | 描述统计                                   | **不参与判定**       | —                               |

### 2.4 分级规则

```
abnormal = {眨眼频率异常, 最长睁眼异常, VMR 异常, 出现下降} 中命中的项
symptomFrequent = 症状频率 ∈ {经常, 几乎总是}

质量门控未过                               → UNKNOWN
|abnormal| ≥ 3，或 |abnormal| ≥ 2 且 symptomFrequent → HIGH
|abnormal| ≥ 1                             → MEDIUM
否则                                       → LOW

borderline（只改建议文案，建议延长或休息后复测）=
  眨眼 9–10 或 16–18 次/分，或最长睁眼 8–12 秒，或 VMR 0.8–0.9，或 |abnormal| == 1
```

症状只在「≥ 2 项异常」时把 MEDIUM 提到 HIGH；LOW 且报告了症状时只改建议文案。年龄、性别、隐形眼镜、屏幕时长、全身病（干燥综合征等）均未进入判定。

### 2.5 问题

| #   | 问题                                                                             | 后果                                                                             |
| --- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| D1  | **眨眼检测依赖帧率**：「连续 3 帧」在 10 fps 时要求闭眼 ≥ 300 ms，正常眨眼的闭眼段常短于此                      | 低帧率设备系统性少记眨眼 → 「眨眼过少」假阳性，同时「最长睁眼」被拉长 → 假阴性。真机记录 3 次/分即此例                       |
| D2  | **EAR 阈值固定 0.23**，不按个人睁眼基线自适应；眼裂小、戴镜、俯视时基线 EAR 本身就低                            | 个体间误检率差异大                                                                      |
| D3  | **常模与任务条件不符**：10–16 次/分是一般条件下的参考，看屏/辨认视标任务会明显抑制眨眼（文献常见降到每分钟个位数）；而干眼者往往眨眼更多而非更少 | 「眨眼过少」在健康人做本任务时可能很常见；方向性也存疑                                                    |
| D4  | **VMR 阈值落在阶梯噪声之内**：0.85 ≈ 0.07 logMAR，小于一档；2-下-1-上阶梯本身就在阈值附近上下游走               | 模拟显示视力稳定者约 16%–29% 触发（附录 B）                                                    |
| D5  | **「下降 ≥ 2 档」= 连续两次答错**，睁眼段约 20 题，偶发失误（lapse）即可触发                               | 模拟显示视力稳定者约 27%–42% 触发                                                          |
| D6  | **超时记为答错且推动阶梯放大**：不作答（走神、没理解、触屏或语音没生效）被当成看不清                                   | 真机记录 12–35 秒连续 13 次超时，阶梯一路跌到 0.1（视标约 90 px），VMR 被算成 0.47，判「看久了容易模糊」——这显然不是视觉下降 |
| D7  | **基线来自 12 秒练习**（约 5–10 题），只是阶梯当时所在位置，不是阈值估计；练习期间还有学习效应                         | VMR 分母噪声大；真机记录睁眼段升到 0.6，比基线 0.5 还好                                             |
| D8  | **同源指标重复计数**：眨眼频率与最长睁眼同出一个检测器；VMR 与下降同出一条阶梯轨迹                                  | 一个传感器故障就能凑出 2 项异常；再叠加症状即 HIGH                                                  |
| D9  | **有用信息没用上**：反应时变化、眨眼前后正确率（研究内容一的核心「眨眼间期」思想）、超时分布、距离波动都算了但不进判定                  | 浪费了最贴近泪膜机制的信号                                                                  |
| D10 | **症状问卷非标准量表**，「经常/几乎总是」二值化后只作为 HIGH 的加分条件                                      | 无法与 OSDI/DEQ-5 等临床量表对照                                                         |
| D11 | 无帧率、无应答比例等质量门控；距离只看是否在 ±5 cm，不看对视标角大小的影响（视标按实测距离换算，影响较小）                       | 低质量数据会被当成有效数据分级                                                                |

## 3 老视（研究内容二）

### 3.1 测试流程与数据

| 任务            | 内容                                                                                              | 记录                  |
| ------------- | ----------------------------------------------------------------------------------------------- | ------------------- |
| 问卷            | 年龄（18–100）、性别、日常矫正方式、屈光情况、近距用眼、职业、眼病、手术及术式/年份；选择「标准模式」（摘老花镜，戴远用镜或不戴）或「日常模式」                     | `profile`、`mode`    |

| 多距离视力         | 60 / 33 / 25 cm 双眼阈值；**每档 3 题、对 ≥ 2 题通过**                                                       | `curvePoints`       |
| 远近切换（调节灵敏度模拟） | 50 cm 与 25 cm 交替真实移动，固定 0.2 档视标，60 秒                                                            | 每题移动耗时、辨认耗时         |

### 3.2 质量门控（任一条 → UNKNOWN）

右/左/双眼任一近视力题数 < 4；有效近点 < 2 次且删失 < 2 次；近点 3 次测量中位绝对偏差 > 5 cm；远近切换题数 < 4 或缺任一距离；多距离有效点 < 2 个；缺年龄。

### 3.3 指标与分级

```
A  = 100 / 近点中位数(cm)        （无有效近点、全部删失时按 100/12 = 8.33 D 计）
Amin(年龄) = 15 − 0.25 × 年龄      （Hofstetter 最小值）
Amean(年龄) = 18.5 − 0.3 × 年龄    （只用于反推「调节年龄」，仅标准模式输出）
阅读需求 = 2.5 D（40 cm）；舒适储备 = 5.0 D（需求 × 2，「保留一半」）

early  = 年龄 < 45 且 A < 5.0 D                 → 「存在较早老视样功能下降」
lower  = A < Amin(年龄)                        → 「调节功能较同龄人偏低」
reduced = 右/左/双眼 40 cm 近视力 < 0.5（或测不出）的眼别集合
cycles  = 远近切换中「相邻两题都答对」的对数（60 秒内）

HIGH   ← early，或 (lower 且 reduced 非空)
MEDIUM ← lower，或 reduced 非空，或 cycles < 3
LOW    ← 其余
```

多距离视力、移近速度、翻转辨认耗时都记录了，但**不进分级**（近点 MAD 只用于质量门控）。日常模式与标准模式**用同一套分级**，只改 `riskScope` 文案和是否输出调节年龄。

### 3.4 问题

| #   | 问题                                                                                                                              | 后果                                       |
| --- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| P1  | **测距未标定**：虹膜测距假设所有人虹膜直径相同，真机记录 `distanceCalibrated: false`。A = 1/d 对误差的敏感度为 δA ≈ δd/d²：20 cm 处 1 cm 误差 ≈ 0.25 D，12 cm 处 ≈ 0.7 D | 近点越近（年轻、调节好）误差越大；虹膜个体差异（约 ±4%）直接变成调节幅度偏差 |
| P2  | **移近法本身倾向高估**：视标物理尺寸固定，越近角尺寸越大，模糊终点被推迟；景深、反应延迟（点按前继续移动）也让近点偏近                                                                   | 与临床负镜片法/推进法存在未知系统偏差，Hofstetter 公式不能直接套用  |
| P3  | **硬年龄切点**：`early` 只对 < 45 岁生效且用固定 5 D；41–44 岁时 5 D 反而高于该年龄的 Amin（44 岁 Amin = 4 D），出现「高于同龄最小值却判 HIGH」                            | 规则内部不一致；44.9 岁和 45 岁结论跳变                 |
| P4  | **日常模式套用标准模式分级**：戴老花镜/渐进镜时测到的「近点」含近附加，和 Hofstetter 比较没有意义                                                                       | 日常模式的 HIGH/MEDIUM 解释不清                   |
| P5  | **屈光状态未参与**：未矫正远视会让测得调节幅度偏低，未矫正近视会让近点偏近；问卷收集了「屈光情况」但不用                                                                          | 混杂因素直接进风险                                |
| P6  | **远近切换主要在测移动手机的速度**：60 秒、真实移动、固定 0.2 大视标（对多数人辨认毫无难度），`cycles < 3` 即 MEDIUM                                                      | 行动慢的老年人被判异常；手机屏幕在固定平面上，调节刺激只由距离变化提供      |
| P7  | **猜测通过率**：4 选 1 时「4 题对 3」纯猜通过概率约 5%；多距离任务「3 题对 2」纯猜通过约 16%                                                                      | 多距离阈值噪声大（不过它目前不进判定）                      |
| P8  | 工作距离固定 40 cm，未问受试者实际阅读距离                                                                                                        | 储备判断与个人需求脱节                              |
| P9  | 三档结论来自文档术语，「较早老视样下降」= HIGH 的临床含义未定义（是否需要转诊？）                                                                                    | ❓见 §9                                    |

## 4 斜视（研究内容三）

### 4.1 测试流程与数据

| 任务   | 内容                                                                                                               | 记录                         |
| ---- | ---------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 问卷   | 孩子年龄、性别、视力、屈光、既往斜视/弱视/手术、协助者                                                                                     | `profile`                  |
| 注视校准 | 3×3 九点，每点等 1.2 秒再采 1.8 秒；每只眼独立仿射映射（屏幕坐标 = a + b·水平 + c·垂直），允许剔除最多 3 个离群点；质量要求水平 r ≥ 0.8、垂直 r ≥ 0.7、RMSE ≤ 10% 屏幕 | 只用于**任务监督**（是否看着目标），不作为诊断量 |
| 稳定注视 | 33 ± 5 cm，1.5 Hz 闪烁卡通目标，12 秒                                                                                     | 每帧左右眼瞳孔中心、角膜映光点、头姿、距离      |
| 交替遮盖 | 遮右 2 s → 去遮 2 s → 遮左 2 s → 去遮 2 s → 右/左各 1 s 交替两轮；协助者在动作的同时点按                                                    | `coverMarks`（真实点按时刻）       |
| 追踪   | 水平正弦 ±10°、周期 4 s × 2；垂直同上；45° 斜向三角波周期 3 s × 2（屏幕放不下时等比缩小）                                                        | `pursuitMaxDeg`（实际可显示角度）   |

帧有效条件（`ScreeningEngine`）：距离 10–100 cm 且在 33 ± 5 cm 内、人脸中心相对段首偏移 ≤ 8%、头姿 |yaw|、|pitch| ≤ 10°、|roll| ≤ 8°、照度 ≥ 50 lx（有传感器时）。光学测量（`EyeOpticalAlgorithm`）：虹膜内取 30% 分位灰度为瞳孔、中位数为虹膜，**瞳孔对比度 ≥ 12 灰阶**才定位瞳孔；映光点为虹膜内小面积高亮连通域（亮度 ≥ max(205, 中位 + 55, 90% 分位 − 8)，对比度 ≥ 55）。

### 4.2 指标

| 指标           | 定义                                                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| 映光偏心         | (映光点 − 瞳孔中心) / 虹膜直径，按鼻侧方向取符号（左右眼对称的 κ 角相减抵消）                                                                                          |
| HDE / VDE（Δ） | 注视段每帧（左眼鼻侧偏心 − 右眼鼻侧偏心）× **175.5**（= 平均角膜直径 11.7 mm × Hirschberg 15 Δ/mm），取中位数；SD 为逐帧标准差                                               |
| 再注视事件        | 每次「去遮盖」点按后 500 ms 窗口内，被解除遮盖眼的偏心**首帧到末帧位移** × 175.5 → 幅度（Δ）、速度（°/s）、相对注视基线的残余（Δ）                                                       |
| BSI          | 0.5·r_h + 0.3·r_v + 0.2·(1 − d_norm)。r_h / r_v 为追踪段双眼（关键点归一化位置）**速度**的皮尔逊相关；d_norm = 双眼相对位置波动 RMS / 水平段眼动幅度，截断到 [0, 1]。理论值域 [−0.8, 1] |

### 4.3 质量门控（任一条 → UNKNOWN「测试质量不佳，请重新测试」）

注视校准未完成；注视/遮盖/追踪任一段「看着目标」的帧 < 60%；水平/垂直/斜向任一段跟随检查未通过（延迟 0–600 ms 内，眼—目标相关 r ≥ 0.30 且位置吻合率 ≥ 60%）；可测阶段有效帧率 < 50%；注视段映光有效帧 < 20 或最长连续有效 < 3 秒；去遮盖可用事件 < 2 次；BSI 无法计算。

### 4.4 分级规则

```
stable      = SD_H ≤ 5Δ 且 SD_V ≤ 2.5Δ                     （稳定阈值为候选值）
fixedSignal = stable 且 (|HDE| ≥ 10Δ 或 |VDE| ≥ 5Δ)        （原文判据）
coverSignal = 再注视幅度中位数 ≥ 6Δ                         （原文判据）

HIGH   「高度疑似斜视」 ← fixedSignal
MEDIUM 「可疑阳性」     ← coverSignal 或 BSI < 0.5
LOW    「未见异常」     ← 其余
（BSI 0.5–0.7 只在文字里写「可疑协调障碍」，不改等级）
```

年龄、屈光、既往斜视史不进判定。

## 6 不需要临床标签的规则层改进

原则：这些改动只依据**测量误差和数据质量**（可以用模拟、工程实验、内部重测得到），不依据「谁有病」——所以现在就能做；但任何改动都要**升规则版本号**（如 `dryeye-9.18-rules-2`），旧记录按旧版本解释；任何会让某类结果从 HIGH/MEDIUM 降为 LOW 的改动，需临床团队书面同意（降为「不确定→复测」可以先做）。

### 6.1 优先级 0：测量层修正（不修这些，任何规则或模型都建在沙上）

| --- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------- |

### 6.2 优先级 1：指标与判定逻辑

**R1 用心理测量模型替代 VMR 与「下降 ≥ 2 档」（干眼）。** 对全部正式试次拟合

```
P(答对 | 档位 L, t) = γ + (1 − γ − λ) · F((L − θ(t)) / σ)，  γ = 1/4（4 选 1 猜中），λ = 失误率
θ(t) = θ₀ + β_open · 1[睁眼段] · t_open + β_blink · 距上次眨眼的秒数
```

- θ₀ 取代「练习基线」，β_open（睁眼段每秒的视力衰减）取代 VMR 与下降时间，β_blink 正是研究内容一「眨眼间期内逐渐变差、眨眼后恢复」的量化。
- λ 吸收偶发失误与无应答，不再把一次走神算成视力下降。
- 用贝叶斯或最大似然估计，直接得到每个参数的**置信区间**；规则改为「β_open 的 95% 区间整体低于 −k」才算异常，区间跨 0 → 「不确定」。
- 该模型可在共享代码里实现（网格后验即可，计算量小），**不需要任何临床标签**；k 的临床意义仍待临床对照（❓），但至少保证稳定者的误报率可控（用附录 B 的模拟器校验 ≤ 5%）。
- 同时建议正式段改为**交错双阶梯**或 QUEST/PEST 类自适应程序，基线改用正式段前若干题的阈值估计而非 12 秒练习终点。

**R2 指标级置信区间 + 保护带 + 三向判定（三病种）。** 每个判定指标都给出区间：

| 指标          | 区间来源                               |
| ----------- | ---------------------------------- |
| 眨眼频率        | 泊松区间（60 秒内 n 次眨眼）                  |
| 最长睁眼        | 眨眼时刻的检测时间误差（由帧率决定）                 |
| β_open / θ₀ | R1 的后验                             |
| 调节幅度        | 近点 3 次测量的离散度 + 测距误差传播（δA ≈ δd/d²）  |
| HDE / VDE   | 中位数的标准误（考虑帧间自相关，按有效独立样本数计）+ 像素定位误差 |
| 再注视幅度       | 事件间离散度 + R6 的噪声底                   |
| BSI         | 按追踪段自助法（bootstrap）                 |

判定改为三向：区间整体在正常侧 → 正常；整体越过阈值 → 异常；**跨过阈值 → 不确定**，触发「延长测试 / 闭眼休息后复测 / 换姿势重测」（干眼已有延长与复测入口）。这与设计文档 §5.2 L4「临界→延长测试，不可信→重测」一致，只是先用解析区间实现，等有校准集后再换成保形预测。

**R3 按证据族计数，消除重复计数。** 干眼分为「眨眼行为族」（频率、最长睁眼）、「视觉稳定族」（β_open、β_blink）、「症状族」（问卷）；HIGH 至少需要两个**不同族**的证据。斜视「眼位族」（HDE/VDE）、「遮盖族」（再注视）、「协调族」（BSI）同理。

**R4 连续质量分并入判定。** 把帧率、有效帧比例、距离稳定度、无应答比例、光学有效率、跟随通过率汇总为 0–1 的质量分 Q（先用加权几何平均，权重可解释），Q 写入记录；Q 低于门槛 → UNKNOWN；Q 中等 → 保护带按 1/Q 放宽（更容易落入「不确定」），而不是当作满分数据。

**R5 老视：连续的年龄相对位置取代硬年龄切点。**

- 用 Hofstetter 三条线（最小 15 − 0.25×年龄、平均 18.5 − 0.3×年龄、最大 25 − 0.4×年龄）给出「本次调节幅度位于同龄参考带的哪个位置」，配合 R2 的区间输出「低于同龄参考 / 处于参考带 / 不确定」，删除 `年龄 < 45 且 A < 5 D` 的跳变规则，或把它改为「A 的区间上界 < 阅读需求 × 2，且 A 的区间上界 < Amin」。
- 日常模式只评估「当前眼镜下 40 cm 与个人阅读距离处的近视力是否够用」，**不与 Hofstetter 比较**。
- 问卷增加「平时手机/阅读距离」，用 1/个人距离 代替固定 2.5 D。
- 未矫正远视、近视（问卷「屈光情况」）作为解释修饰：如标准模式下自述远视且未戴远用镜，则调节幅度结论降为「不确定，建议验光后复测」。
- 移近法视标改为**按实测距离实时缩放、保持角尺寸不变**，去掉角放大导致的终点推迟（协议改动，需临床确认 ❓）。
- 远近切换改用「辨认耗时」（已记录 `clarityMs`、`movementMs`）而非完成循环数，排除挥动手机的动作速度；或在临床确认前不参与分级。
- 近视力与多距离任务把通过规则改为降低猜测率的规则（如每档 5 题对 4 题，纯猜通过约 1.6%），或用 R1 同类的心理测量拟合求阈值。

**R6 斜视：去噪底、对齐事件、限制 BSI。**

- 「注视稳定」改为对**去除测量噪声后**的 SD 判定（测量噪声由同一帧序列的高频成分或静态假眼/照片实验估计），并且当 |HDE| 区间下界 ≥ 10Δ 时不再要求稳定条件——噪声不能把高度疑似压低（S4）。
- 再注视：在点按后 0–800 ms 内按速度峰值检测扫视，取扫视前后各 100 ms 平台的位移；从同一受试者「没有遮盖动作」的随机窗口计算同一指标作为**零分布**，事件幅度须超过零分布 95 分位且 ≥ 6Δ 才算阳性。
- BSI：只有当可显示追踪幅度 ≥ 某下限（如 ±8°，❓）且两眼跟随都通过时才计算；否则标「本机屏幕不足以评估双眼协调」。在常模建立前，BSI < 0.5 不单独触发 MEDIUM，只作为辅助描述（这是一项可能降低敏感度的改动，须临床同意 ❓）。
- 增加**聚散（左右眼位置差）**在角度单位下的指标，作为对共同性斜视更敏感的协调指标（需要 M5 的光学测量可用）。

**R7 个人纵向变化（不需要疾病标签，需要内部重测研究）。** 组织 20–30 名团队成员/志愿者，每人同一设备、同一天及间隔一周各测 2–3 次，得到每个指标的标准测量误差 SEM。之后同一被测者两次测试的变化用**可靠变化指数** RCI = (x₂ − x₁) / (√2 · SEM) 判断，|RCI| > 1.96 才报告「较上次明显变化」。服务端已有 `/history`、`/compare` 接口可直接承载。

**R8 设备层校正。** 记录设备型号、相机分辨率、实际帧率、屏幕像素密度来源；数据积累后对同一指标做「设备随机效应」估计（同一批受试者在多台设备上测，或大样本下按设备比较分布），把设备偏移写入版本化的设备配置——这同样不需要疾病标签。

**R9 规则配置化 + 模拟回归测试。** 把所有阈值、保护带、证据族定义集中到一个带版本号的配置对象（三端共享，服务端复算用同一份）；为每条规则建立「稳定观察者 / 纯噪声 / 已知偏斜」的模拟数据集，单元测试断言误报率与检出率（例如稳定观察者在 R1 下的干眼视觉族误报率 ≤ 5%）。附录 B 的脚本可作为起点。

### 6.3 改动后的规则输出形态（建议）

```
质量 Q、拒判理由
├─ 证据族 1：指标值 [区间]  → 正常 / 异常 / 不确定
├─ 证据族 2：...
└─ 合成：任一族「不确定」且无族「异常」→ 「结果不确定，建议延长/复测」
         两个不同族异常 → HIGH；一族异常 → MEDIUM；全部正常 → LOW
         红旗（如 |HDE| 区间下界 ≥ 10Δ）→ 至少 HIGH，不受其他族影响
```

这仍然是确定性、可解释、离线可跑的规则，正好作为 §7 模型的安全底线。

## 7 机器学习 / 深度学习路线

### 7.1 总原则（与设计文档 §5 一致）

1. **规则是底线，模型是校准过的评分器**：最终等级 = max(规则底线, 模型等级)，模型不能下调；质量门控失败时模型不运行。
2. **临床检查结果只能做标签，不能做输入**（手机自测时拿不到）。
3. **按受试者划分**训练 / 校准 / 测试集；同一人的多次测试只能在同一集合；另留**设备外**（未见过的机型）和**中心外**（另一研究点）验证集。
4. **影子模式**：模型先在服务端对已上传记录打分、只记录不展示，离线评估达标并经外部验证后才转 `ACTIVE`。
5. **版本绑定**：每个模型记录输入特征版本、规则版本、训练快照、校准参数和指标；特征版本不匹配或输入越出训练分布时自动退回纯规则，并在报告中注明。

### 7.4 校准、不确定性与拒判

- **概率校准**：在独立的校准集上做 Platt 缩放或保序回归；报告校准曲线、Brier 分数、按年龄组/设备的校准斜率。
- **保形预测**：用分组（Mondrian）保形，按类别或年龄组分别保证覆盖率，输出预测集；预测集同时含「低」与「高」→ 「结果不确定」，触发延长/复测（§5.2 L5 第 4 条）。
- **选择性预测**：画「覆盖率—风险」曲线，确定拒判比例与剩余样本准确率的取舍，作为产品决策依据（❓可接受的拒判率）。
- **分布外**：特征越界、未见过的设备型号、质量 Q 低 → 模型不参与，退回规则。

### 7.5 样本量与验证

- 预测模型样本量建议按 Riley 等的预测模型样本量准则计算（取决于候选特征数、阳性率和期望的收缩），十余个候选特征的表格模型通常需要**每类数百例**；原文斜视方案的 ≥ 500 例病例/对照 + 正常常模 + 100 例重测，是合理的量级。现有 `screening_model.py` 的「每类至少 5 名受试者」只是软件下限，不是统计下限。
- 指标：AUC、预设操作点的敏感度/特异度（含置信区间）、PPV/NPV（按目标人群患病率换算）、校准、决策曲线；连续量用 RMSE、相关、Bland–Altman；重测用 ICC / 加权 Kappa。
- 报告规范：建模按 TRIPOD+AI，诊断准确性按 STARD；亚组（年龄、设备、iOS/安卓、戴镜、肤色/虹膜颜色）单独报告。
- `screening_model.py` 的下一步：分组交叉验证（GroupKFold）、自助法置信区间、校准输出、单调约束；这需要引入 numpy / scikit-learn / LightGBM 等免费开源依赖（❓是否接受离开「仅标准库」的约束）。

沿用设计文档 §5.4，不做新增决定：LLM 只读结构化结果（等级、触发的规则与证据族、模型特征贡献、质量、年龄段）和经审核的知识库片段；输出固定章节并后置校验（禁止诊断性措辞、禁止出现输入中没有的数值、必须含「初筛参考，不能替代眼科诊断」），校验失败回退模板。供应商（国内 API / 私有部署 / 暂不启用）仍待决定，**在决定前不发送任何数据**。本文 §6.3 的分族输出本身就是很好的 LLM 输入结构，也能直接驱动更好的模板报告——建议先把模板报告做好，LLM 只做改写。

## 9 需要临床团队（及产品）回答的问题

1. ❓**每个病种的金标准与标签定义**：干眼按 TFOS DEWS II 还是《中国干眼专家共识 2020》？老视的标签是「需要近附加」、临床调节幅度，还是近附加度数？斜视以 PCT 近距 Δ、遮盖-去遮盖分类，还是两者都要？
2. ❓**三级结果的临床动作**：HIGH / MEDIUM / 「不确定」分别对应「尽快就医 / 择期检查 / 复测」吗？「不确定」最多复测几次、保留哪一次？
3. ❓**干眼任务中眨眼频率的参考范围**：原文 10–16 次/分是否适用于「看屏辨认视标」这种会抑制眨眼的任务？是否接受先用健康志愿者在本任务下的分布替代？方向上是「过少」还是「过多」提示干眼？
4. ❓**「正常眨眼间隔 > 10 秒」的含义**：是否就是 20 秒睁眼段的最长持续睁眼（本项目的解释）？
5. ❓**视觉稳定性的临床意义门槛**：R1 的 β_open（每秒 logMAR 变化）达到多少算有意义？能否参照现有功能性视力（FVA）研究给出初值？
6. ❓**老视移近法视标**：是否同意改为「保持角尺寸不变」的动态视标？标准模式下自述远视/近视但未戴远用镜者如何处理？日常模式是否只报告近视力是否够用？
7. ❓**远近切换任务**：是否继续作为分级依据，还是在验证前只作为描述？
8. ❓**斜视规则中可能降低敏感度的改动**：BSI < 0.5 不再单独触发「可疑阳性」、BSI 需要最小追踪幅度，是否同意？Hirschberg 比值是否按年龄采用不同值？
9. ❓**眼区图像采集**：是否允许在单独同意下采集短时眼区图像用于标注测量层模型（瞳孔/映光/眨眼）？保存期限与盲法复核流程？（对应设计 §9 第 7 条、需求文档 C08）
10. ❓**健康对照常模**：入组与排除标准、年龄分层（儿童 3–5 / 6–8 / 9–12 岁的原文写法待核对）、每层样本量。
11. ❓**可接受的拒判/复测率**：用户体验与安全之间的取舍，例如「不确定」比例不超过多少。

## 附录 A：真机记录剖析（iPhone，2026-10）

### A.1 干眼 `dryeye_1792114601183.json`

- 结果：`MEDIUM`，异常 2 项：「每分钟眨眼约 3 次，比正常少」「视力保持度只有 47%」。症状频率「有时」，未升 HIGH。
- 眨眼：80 秒内只记到 4 次（9.2、15.9、36.7、68.1 秒），自然段 3 次 → 3 次/分。当时相机分析约 5–10 fps，按附录 B 的模拟 3 帧判定在此帧率下检出率很低，**这条异常基本是测量伪差**（D1）。最长睁眼 11.9 秒「正常」也是少记眨眼的产物。
- 视标：自然段 37 题、睁眼段 17 题，共 17 次超时。12–35 秒**连续 13 次超时**，阶梯从 0.25 跌到 0.1（视标约 90 px，任何能看到 0.5 的人都不会看不清），37 秒后恢复作答，几乎全对并一路升到 0.4；睁眼段 17 题全对，升到 0.6（高于基线 0.5）。VMR = 0.47 完全来自无应答段（D6），而「下降时间」为空、睁眼段反而最好——与「看久了容易模糊」的结论相反。
- 数据质量门控全部通过（有效帧 100%、距离达标 92%、头部偏转 2%），说明**现行门控抓不住这两类问题**（帧率、无应答）。M1、M4 可分别把这两条异常改判为「不可评估」。

### A.2 斜视 `strabismus_1792114997048.json`

- 结果：`UNKNOWN`（质量不足），这是正确的拒判。
- 光学：`opticalRejectionCounts` = 左眼「瞳孔对比度不足」2,258、左眼「未识别到可靠角膜反光点」50、等待人脸 2；`opticalValidFrames` = 0，`leftNasal` 全部为空（S1）。拒绝原因只记先失败的左眼。
- 帧：相机 2,310 帧，测试段计数 769 帧，写入 `eyeSamples` 262 帧；帧间隔中位 67 ms（约 15 fps）、90 分位 333 ms（S7）。
- 追踪：屏幕在 33 cm 处只能显示水平 ±4.8°、垂直 ±8.4°；r_h = 0.04、r_v = 0.89、d_norm = 0.51、BSI = 0.39。水平幅度小时 r_h 被噪声主导（S6）；若质量门控通过，此 BSI 会单独触发「可疑阳性」。
- 遮盖：9 个动作全部有点按，但第一次「遮右」到「移开」间隔约 8 秒（协议 2 秒），说明协助者节奏与协议差异大，事件窗口算法需要容忍这种差异。

## 附录 B：规则误报与帧率影响的模拟

脚本存放在会话共享笔记目录（`rule-false-alarm-sim.py`，仓库外），纯标准库，可复现。

**B.1 稳定观察者下干眼视觉指标的误报率。** 假设：4 选 1，猜中率 1/4；逻辑型心理测量函数，斜率 0.03 或 0.06 logMAR；失误率 2% 或 5%；**真实视力全程不变**（0.5 或 1.0）；每题约 1 秒；12 秒练习定基线后走 60 + 20 秒正式测试，阶梯与档位与代码一致（未模拟像素封顶和超时）。每种条件 20,000 次。

| 条件                   | P(VMR < 0.85) | P(睁眼段下降 ≥ 2 档) | P(至少一项) |
| -------------------- | ------------- | -------------- | ------- |
| 真实 0.5，斜率 0.03，失误 2% | 0.19          | 0.29           | 0.42    |
| 真实 0.5，斜率 0.06，失误 5% | 0.22          | 0.42           | 0.55    |
| 真实 1.0，斜率 0.03，失误 2% | 0.29          | 0.27           | 0.48    |
| 真实 1.0，斜率 0.06，失误 5% | 0.16          | 0.42           | 0.51    |

含义：在现行规则下，**视力完全不变的人约有一半会因阶梯随机游走被记一项视觉异常**，单此一项即 MEDIUM。具体数值依赖上述假设，但量级足以说明 VMR 0.85 与「2 档」都落在测量噪声之内（D4、D5）。

**B.2 帧率对「连续 3 帧」眨眼判定的影响。** 假设 EAR 低于阈值的持续时间在 80–300 ms 间均匀分布、相位随机：

| 帧率  | 5 fps | 10 fps | 15 fps | 20 fps | 30 fps | 60 fps |
| --- | ----- | ------ | ------ | ------ | ------ | ------ |
| 检出率 | 0.00  | 0.23   | 0.61   | 0.79   | 0.97   | 1.00   |

闭眼时长分布是假设值，应以真实高帧率录像校正；但「以帧数计的判据随帧率剧烈变化」这一结论不依赖具体分布（D1、M1、M2）。
