# EyeProject 交接文档（迁移到新电脑）

> 本文档用于把整个项目从当前电脑迁移到另一台电脑，从零恢复开发/构建环境。
> 生成时间：2026-08-17。项目路径：`E:\workspace\EyeProject`。

## 一、项目概览

**EyeProject =「眼健康助手」**，把旧的 `EyeProtect_handoff_2026-07-24`（Kotlin View + CameraX + ML Kit）
重构为 **Jetpack Compose + MediaPipe Face Landmarker**，按 **Now in Android（NIA）** 官方多模块架构组织，
UI 完全自绘（不含 Material 默认组件）。

核心功能：前置摄像头实时检测 → 眼部关键点（MediaPipe 478 点含虹膜）→ 40cm 标定距离估算 →
过近提醒；外加屏幕使用时长、亮度、环境光照、全局护眼色温滤镜、定时护眼提醒；
以及一个「模型测试」页（LiteRT 跑自定义 `.tflite`，如 L2CS-Net 注视估计）。

## 四、新电脑环境搭建（从零）

1. **装 JDK 17**，设 `JAVA_HOME`（新机路径自定）：
   ```powershell
   setx JAVA_HOME "D:\path\to\jdk-17"
   ```
2. **装 Android SDK**：需 platform **android-37**（compileSdk 37）、build-tools（AGP 会自动下载缺失组件）。
   在项目根目录生成/修改 `local.properties`：
   ```properties
   sdk.dir=D:\\path\\to\\Android\\Sdk
   ```
   > `local.properties` 是机器专属，不随仓库提交，新机用 Android Studio 打开会自动生成。
3. **装 Android Studio**（可选，用于同步/调试）或仅用命令行 Gradle。

## 五、构建步骤

```powershell
cd EyeProject
.\gradlew.bat assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`（约 97 MB，含 MediaPipe tasks + LiteRT C++ 原生库）。

> 首次构建会下载 Gradle 9.5.0 分发包 + 依赖（几百 MB），需联网；必要时走代理。

## 七、关键配置说明（⚠️ 迁移时重点看）

`gradle.properties` 里有两类配置，**沙箱专属的请按需清理**：

| 配置 | 是否必需 | 说明 |
|---|---|---|
| `android.disallowKotlinSourceSets=false` | ✅ **必须保留** | Hilt+KSP 在 AGP9 内置 Kotlin 下的必需放行，否则配置期报错 |
| `org.gradle.configuration-cache=true` | 可选 | 配置缓存 |
| `-Djava.io.tmpdir=E:/workspace/.gradle-tmp` | ❌ 沙箱专属 | 新机可删（回退默认临时目录） |
| `kotlin.compiler.execution.strategy=in-process` | ❌ 沙箱专属 | 新机可删（沙箱内 Kotlin 守护进程受限才需要） |

`app/build.gradle.kts` 里的 `signingConfigs.sandboxDebug` 是**沙箱专属**（沙箱无法写 `~/.android`，
才用了工作区内 keystore `E:\workspace\.android-debug\debug.keystore`）。新机正常环境可删掉该块，
改回默认 debug 签名（`~/.android/debug.keystore` 会自动生成）。

> 当前项目里**已移除代理配置**（之前用 `systemProp.*.proxyHost`，因代理对 Maven Central 不稳定而移除）。

## 十、已知注意点

1. **Hilt × AGP9**：靠 `android.disallowKotlinSourceSets=false` 解决，务必保留。
2. **MediaPipe 图像格式**：`ImageAnalysis` 已设 `OUTPUT_IMAGE_FORMAT_RGBA_8888`（否则 MediaPipe 抛异常）。
3. **旋转/镜像**：MediaPipe 关键点坐标已按 `rotationDegrees` 转正处理；若新设备方向异常，检查
   `feature/camera/FaceLandmarkerAnalyzer.kt` 的旋转逻辑。
4. **约定插件的 AGP 依赖是 `implementation` 不是 `compileOnly`**（Gradle 9 行为差异），勿改。
5. **通知小图标**：在 `core/notifications/src/main/res/drawable/ic_stat_eye.xml`（自定义眼睛图标）。
6. 应用图标为自定义眼睛图标（`app/src/main/res/drawable/ic_launcher_foreground.xml` + 黄色背景）。
7. **LiteRT C++ SDK（testmodel）**：CMake 首次 configure 会 `FetchContent` 联网拉 abseil/flatbuffers/OpenCL；
   `libgaze_native.so` 由 CMake 编译（源码在 `feature/testmodel/src/main/cpp/`），JNI 桥入口
   `Java_com_zkyjss_eyeproject_feature_testmodel_GazeNative_run`（对应 `GazeNative.kt`）。
8. **NDK 27**：`app`/`feature:camera`/`feature:testmodel` 三个模块都指定了 `ndkVersion = "27.3.13750724"`；
   若本机 NDK 28 已修复可移除，但 CMake 侧仍建议用 27 验证过的版本。
9. **testmodel 数据流**：`Camera → toBitmap → uprightBitmap（旋转正立）→ FaceDetectorAnalyzer（MediaPipe FaceDetector 检人脸框）
   → cropBitmap（裁剪人脸）→ GazeNativeModel.infer_use_android_api → [yaw,pitch]`。
   两条推理路线：`infer_use_cpp_lib`（C++ JNI，`libgaze_native.so`）与 `infer_use_android_api`（Maven litert 2.1.1 的 Java API）。
10. **⚠️ 裁剪坐标必须与检测框坐标系一致**：`FaceDetectorAnalyzer` 是在「旋转到正立」的图上检测，
    `latestBitmap` 也必须用 `uprightBitmap()` 旋转到正立，否则 `cropBitmap` 会用旋转后的坐标裁剪未旋转的图，
    导致人脸区域错位、视线角度不明显（这是踩过的坑）。
