# 眼健康助手 · 后端部署说明

给负责部署的同学（或其 AI 助手）看的说明，力求照着做就能上线。
程序细节见仓库 `backend/server/SERVER.md`。

> **当前版本：`eyeproject-server-0.2.0.zip`（2026-10-31）。已经部署过 0.1.0 的，直接看第 0 节「从 0.1.0 升级」。**

## 0. 从 0.1.0 升级（已部署过的看这里）

本版更新：

- AI 对话改由爱尔眼科数字人「爱科 Eyecho」主持（模型人设与提示文案从「小瞳」改为「爱科」）。
- 新增**主动问询**：用户说「帮我一步步梳理眼部不适」或描述不适时，爱科一次问一个关键问题并给出可点选项，信息够了先做最后确认，再给出五段总结（综合判断、就医建议、就医前的缓解与注意事项、需要警惕的信号、复诊与跟进）。
- 安全规则：提到眼痛、突然看不清等危险信号时，回答必须建议尽快就医，且不再继续追问；「结束问询」由规则直接回复，不调用模型、不占每日条数。
- 数据库**无新迁移**（仍是 V1–V4），配置文件**无必须新增的变量**；对话内容依旧不入库。

升级步骤（约 2 分钟，期间接口短暂不可用）：

```bash
sudo unzip eyeproject-server-0.2.0.zip -d /opt/eyeproject      # 与旧版并列：/opt/eyeproject/eyeproject-server-0.2.0
sudo chown -R eyeproject: /opt/eyeproject
sudo sed -i 's#eyeproject-server-0.1.0#eyeproject-server-0.2.0#g' /etc/systemd/system/eyeproject.service
sudo systemctl daemon-reload && sudo systemctl restart eyeproject
journalctl -u eyeproject -n 50                                  # 确认已监听 8080、没有报错
curl https://主页域名/eyeapi/health                             # {"status":"ok"}
```

- 回滚：把 `ExecStart` 路径改回 `0.1.0`，`daemon-reload` 后重启即可（本版没有数据库迁移，可以直接回退）。旧目录确认新版正常后再删。
- 手机端要装**新版 App** 才会出现问题卡和选项；旧版 App 连新后端仍是普通对话，新版 App 连旧后端也只有普通对话。
- 想换成课题组自己部署的大模型，见第 7 节「换用自部署模型」。

## 1. 先说结论

- **不需要算力**：没有 GPU，不跑模型。眼部检测都在手机上完成；AI 解读、AI 综合建议和与爱科的对话调用外部大模型接口（默认 DeepSeek，也可换成课题组自部署的 OpenAI 风格接口）。1 核 2 GB 的普通 Linux 服务器就够用。
- **但它不是网页**：它是一个**常驻运行的 Java 接口服务**，外加一个**数据库**。
  - 如果组里主页只是静态网页托管（只能放 HTML/图片，例如 GitHub Pages、学校建站系统），**放不了**。
  - 如果主页跑在组里自己的 Linux 服务器上（nginx / Apache），**可以**在同一台机器上加一个子路径（如 `https://主页域名/eyeapi/`）或子域名（如 `https://eye.主页域名/`），与主页互不影响。
- **App 怎么用它**：手机 App 在「我的 → 右上角人像（账户）→ 服务器地址」（未登录时可改）里填部署好的 https 地址，即可注册、登录、同步测试记录、使用 AI 解读与和爱科对话。（App 默认已填课题组地址 `https://geometrylearning.com/eyeapi`。）没有网页界面，浏览器打开只能看到 `/health` 健康检查。

## 2. 架构

```
手机 App ──HTTPS──▶ nginx（主页域名，443） ──▶ 127.0.0.1:8080 Java 服务 ──▶ PostgreSQL（本机）
                                                        └──HTTPS 出站──▶ api.deepseek.com 或自部署模型（AI 功能，可不开）
```

- 对外只开 443；8080 和数据库端口只监听本机。
- 服务存的是**健康数据**（测试结果、问卷），按账号隔离，问卷与原文在库里用 AES-256-GCM 加密，密钥只在服务器环境变量里。

## 3. 服务器要求

| 项 | 要求 |
|---|---|
| 系统 | Linux（Ubuntu 22.04 / 24.04、Debian 12、CentOS Stream 9 等均可） |
| 配置 | 1 核 / 2 GB 内存 / 10 GB 磁盘起步。登录时口令哈希会短暂占满一个核，属正常 |
| 软件 | JDK **17 或以上**（`openjdk-17-jre-headless` 即可）、PostgreSQL **14 或以上**、nginx |
| 网络 | 一个能配 HTTPS 证书的域名（可用主页域名的子路径）；服务器能出站访问 `https://api.deepseek.com`（不开 AI 解读可不需要） |

## 4. 获取程序

二选一：

- **A. 用打好的包（推荐）**：项目方提供 `eyeproject-server-0.2.0.zip`。解压到 `/opt/eyeproject`，启动脚本为 `bin/eyeproject-server`，所有依赖、数据库迁移脚本和知识库都已打包在内。
- **B. 从源码构建**：需要仓库访问权限和 JDK 17。在仓库根目录执行 `./gradlew -p backend/server distZip`，产物在 `backend/server/build/distributions/`。

```bash
sudo useradd --system --home /opt/eyeproject --shell /usr/sbin/nologin eyeproject
sudo mkdir -p /opt/eyeproject && sudo unzip eyeproject-server-0.2.0.zip -d /opt/eyeproject
# 解压后是 /opt/eyeproject/eyeproject-server-0.2.0/{bin,lib}
sudo chown -R eyeproject: /opt/eyeproject
```

## 5. 数据库

```bash
sudo -u postgres psql <<'SQL'
CREATE USER eyeproject WITH PASSWORD '换成随机强口令';
CREATE DATABASE eyeproject OWNER eyeproject ENCODING 'UTF8';
SQL
```

建表不用手动做：服务每次启动会用 Flyway 自动执行迁移（`V1__init`、`V2__subject_profile`、`V3__ai_explanation`、`V4__ai_chat_usage`）。

## 6. 生成密钥（只做一次，务必备份）

```bash
openssl rand -base64 32   # 输出作为数据加密密钥，写成 k1:<输出>
openssl rand -hex 32      # 输出作为审计盐
```

> **数据加密密钥丢了，库里加密的问卷与记录原文就再也解不开。**
> 请把密钥和数据库备份**分开**保存（例如密钥放组里的密码管理器）。不要把它提交到任何代码仓库或主页仓库。

## 7. 配置文件

`/etc/eyeproject/server.env`（权限 `600`，属主 `eyeproject`）：

```ini
EYE_ENV=production
EYE_PORT=8080
EYE_DB_URL=jdbc:postgresql://127.0.0.1:5432/eyeproject
EYE_DB_USER=eyeproject
EYE_DB_PASSWORD=第 5 步的口令
EYE_DATA_KEYS=k1:第 6 步的 base64 输出
EYE_AUDIT_SALT=第 6 步的 hex 输出
# 位于 nginx 之后：信任 X-Forwarded-* 头，并据此要求 HTTPS
EYE_TRUST_PROXY=true
EYE_REQUIRE_HTTPS=true
# AI 功能（解读、综合建议、和爱科对话）：Key 由项目方单独提供；不填则其余功能正常，AI 功能显示「暂不可用」
DEEPSEEK_API_KEY=
# 每个账号每天最多调用大模型的次数（控制费用）
EYE_LLM_DAILY_LIMIT=20
# 每个账号每天和 AI 对话（和爱科聊聊）的条数上限
EYE_LLM_CHAT_DAILY_LIMIT=40
# 数据看板（管理网页）口令，至少 12 位；不填则不开放看板（/admin 返回 404）
EYE_ADMIN_PASSWORD=
```

生产模式下缺少 `EYE_DB_URL`、`EYE_DATA_KEYS` 或 `EYE_AUDIT_SALT` 时服务会拒绝启动，这是有意的设计。
其余可选变量（保留期、限速等）见 `SERVER.md` 的「环境变量」表。

### 换用自部署模型（可选）

接口要求是 **OpenAI 风格**（`POST {地址}/chat/completions`），例如 vLLM、Ollama、LM Studio、Xinference 等自带的 OpenAI 兼容服务。在 `server.env` 里把 DeepSeek 那一行换成：

```ini
EYE_LLM_BASE_URL=http://模型服务地址:端口/v1     # 填到 /v1 为止，程序会自己拼 /chat/completions
EYE_LLM_MODEL=部署时的模型名
EYE_LLM_API_KEY=模型服务的 Key（没有就随便填一个非空值）
EYE_LLM_DISABLE_THINKING=false                    # 必须改成 false：默认会带 DeepSeek 专用的 thinking 字段
EYE_LLM_TIMEOUT_MS=60000                          # 本地模型较慢时适当放宽（nginx 的 proxy_read_timeout 要更长）
```

注意：

- 模型必须支持 `response_format: {"type":"json_object"}`（JSON 模式），否则回答会因格式不合格被拒、显示「暂时联系不上大模型」。建议用 7B 以上、中文好的指令模型（如 Qwen2.5-7B/14B-Instruct）。
- `DEEPSEEK_API_KEY` 优先级高于 `EYE_LLM_API_KEY`，换模型时把 `DEEPSEEK_API_KEY` 那一行删掉或留空。
- 改完 `systemctl restart eyeproject`，在 App 里和爱科说一句「帮我一步步梳理眼部不适」，能出现问题卡和选项就说明模型守得住格式。

## 8. 开机自启（systemd）

`/etc/systemd/system/eyeproject.service`：

```ini
[Unit]
Description=EyeProject API
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
User=eyeproject
WorkingDirectory=/opt/eyeproject
EnvironmentFile=/etc/eyeproject/server.env
Environment=JAVA_OPTS=-Xmx512m -Dfile.encoding=UTF-8
ExecStart=/opt/eyeproject/eyeproject-server-0.2.0/bin/eyeproject-server
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now eyeproject
journalctl -u eyeproject -f          # 看到监听 8080 即启动成功
curl http://127.0.0.1:8080/health    # 应返回 {"status":"ok"}
```

## 9. nginx 反向代理

在主页现有的 `server { listen 443 ssl; ... }` 块里加一段即可，二选一。

**子路径**，App 里填 `https://主页域名/eyeapi`：

```nginx
location /eyeapi/ {
    proxy_pass http://127.0.0.1:8080/;      # 末尾的 / 会去掉 /eyeapi 前缀，不能省
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $host;
    client_max_body_size 20m;               # 单次同步上限约 16 MB
    proxy_read_timeout 90s;                 # AI 请求最长约 60 秒（超时 30 秒 × 最多重试 2 次）
}
```

**子域名**，App 里填 `https://eye.主页域名`：新建一个 `server` 块，证书覆盖该子域名，`location /` 内容同上，`proxy_pass` 改为 `http://127.0.0.1:8080;`。

`X-Forwarded-Proto` 必须带上：服务据此确认请求走的是 HTTPS，否则会拒绝业务请求（`/health` 除外）。

## 10. 验证

```bash
curl https://主页域名/eyeapi/health      # {"status":"ok"}
curl -i https://主页域名/eyeapi/v1/me    # 401，说明认证生效（未登录）
```

然后在手机 App 里操作：「我的 → 右上角人像（账户）→ 服务器地址」（未登录时可改）填上面的地址 → 注册 → 做一次测试 → 云端同步打开 → 记录出现在云端。
想测 AI：在测试结果页点「AI 解读」；首页「AI 综合建议」进入和爱科的对话，发「帮我一步步梳理眼部不适」应出现问题卡。需要已配好模型 Key（第 7 节）。

### 数据看板

填了 `EYE_ADMIN_PASSWORD` 后，浏览器打开 `https://主页域名/eyeapi/admin/` 输入该口令即可。nginx 不用另配。

- 能看到：注册账号数、同意研究用途的账号数、各项测试的风险分布、最近 30 天测试次数、平台分布，以及逐条测试记录（测试时间、类型、风险等级、数据质量、年龄段、关键指标）；可按测试、等级、日期筛选，可导出 CSV。
- 只含**最新一次同意了「研究用途」**的账号；用户与被测者显示为不可逆的假名编号，看不到邮箱、昵称、问卷与记录原文。
- 登录 8 小时后失效，服务重启也需重新登录；口令每 IP 每分钟最多试 5 次。每次登录、查看与导出都写审计日志。
- 改口令：改 `server.env` 后 `systemctl restart eyeproject`。

## 11. 日常运维

| 事项 | 做法 |
|---|---|
| 备份 | 每天 `pg_dump -Fc eyeproject > /backup/eyeproject-$(date +%F).dump`，保留 30 天。密钥另存，见第 6 步 |
| 日志 | `journalctl -u eyeproject`。日志不含请求体、令牌、邮箱和健康内容 |
| 升级 | 见第 0 节：解压新版本 zip → 改 `ExecStart` 路径 → `systemctl restart eyeproject`。数据库迁移自动执行，旧数据保留 |
| 清理 | 服务每天自动清理过期令牌、审计与 30 天前的 AI 解读缓存，无需定时任务；对话内容本来就不入库 |
| 换密钥 | `EYE_DATA_KEYS=k1:旧,k2:新`，`EYE_ACTIVE_KEY_ID=k2`；旧 key 必须保留，用于解密旧数据 |
| 费用 | 只有调用 DeepSeek 时按量计费：AI 解读每次约 0.002 元；和爱科对话每条约 0.003–0.005 元。每账号每天上限分别由 `EYE_LLM_DAILY_LIMIT`、`EYE_LLM_CHAT_DAILY_LIMIT` 控制。自部署模型不产生接口费用 |

## 12. 安全与合规注意

- 防火墙只放行 80/443；**不要**对外开放 8080 和 5432。
- 这是健康数据。目前定位是**课题组内部测试**；正式对外招募用户前，还需要：
  - 知情同意与伦理流程；
  - 与 DeepSeek 的数据处理约定（解读与综合建议只发结果等级与指标；对话会发送用户自己输入的文字与去标识用眼概况；都不含姓名、账号）。换成自部署模型可避免数据出校；
  - 知识库内容经眼科医生审核。
- 密钥、数据库口令、模型 Key 只放在 `/etc/eyeproject/server.env`，不进任何仓库，也不贴进聊天记录。
