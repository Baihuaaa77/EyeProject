# 记录与健康档案改进

本次按 newpart 评估中明确可借鉴的部分，完善记录查看/导出、干眼数据可靠性说明、家庭成员健康资料。Android 与 iOS 使用同一份字段、记录解析和报告文案。

## 使用入口

1. **我的 → 本机测试记录**：点开记录查看建议与要点，按组展开关键指标、依据、数据可靠性、测试时资料及设备信息。可分别导出文字报告 TXT 和原始 JSON。文字报告便于直接阅读，JSON 保留逐题/逐帧数据用于复核。
2. **干眼测试结果**：新增「数据可靠性说明」，先显示一句概况，展开查看限制；「查看本次数据 → 数据可靠性」包含距离波动、帧率与阶段作答等明细。
3. **我的 → 家庭成员与资料**：新增以下可选内容，照检查单填写，不清楚可留空。

## 健康资料新增内容

| 分组 | 内容 |
|---|---|
| 视力与验光 | 验光日期；左右眼裸眼/矫正小数视力；左右眼球镜、柱镜（D，支持正负号）、轴位（0–180°） |
| 近期眼部用药 | 在原有近期用药选项下补充药名、频次、开始/结束日期；结束日期不得早于开始日期 |
| 隐形眼镜 | 根据原有佩戴史，补充类型、更换周期和每日佩戴时长 |
| 其他病史 | 家族眼病史、已知过敏、眼病与手术补充说明 |

新字段继续保存在当前成员资料中，通过既有加密资料同步接口同步。原资料键、成员编号、测试必填项不变；字段总数保留在现有服务端的 64 项上限内。选填数值限制用于拦截格式/单位错误，不是病情判据。

## 记录兼容与数据含义

- 新记录保存当时的报告快照与评估版本，打开历史记录不会随软件升级重算结论。资料显示测试当时的快照，不用成员的最新资料替换。
- 旧记录不改写，按已有摘要、指标、证据和问卷读取；未保存的数值明确显示「未记录」。不确定结果不会显示成未见异常，质量不足不会显示成低风险。
- 两种导出均不改动源记录、原始 JSON 字节和同步发件箱；可在未登录、离线时使用。
- 干眼距离波动基于正式阶段约每 500 ms 的采样，未检测到距离的读数不参与均值/标准差，另计无读数比例。该统计描述采集条件，不代表距离测量已校准。
- 本次没有替换 OCEC 模型、视标体系、风险评分或后端，也不增加新的干眼判级阈值。

## 复核后的调整（2026-10-20）

- **数据可靠性卡片只在结果有效时显示**：无效结果的原因已在「这次没测好」卡片列出，原先会在两张卡片里重复（安卓、iOS 同改）。
- **视标呈现确认**（评估文档 §3.2）：干眼每题先发出显示，界面经两次帧回调（安卓 `withFrameNanos`、iOS `CADisplayLink`）回报已画出后，反应时与 2 秒时限才从此刻起算；旧题号和重复回报忽略；界面 250 ms 内未回报（切后台、测试替身）时仍按发出时刻计，不会卡住。每题记录 `presentDelayMs`，「数据可靠性」显示已确认题数与中位延迟。这只说明计时起点，不是屏幕发光时刻的硬件测量。
- **主动「看不清」与答错、超时分开统计**（§3.3）：可靠性明细改为「答对 · 答错 · 看不清 · 超时」，评估规则不变。
- **距上次眨眼的作答分箱**（§3.3，描述性）：「查看本次数据」新增「距上次眨眼的作答」：0–1、1–2、2–3、3–4、≥ 4 秒与首次眨眼前，各显示题数、答对率、正确作答平均反应；空箱写「无数据」，不参与判级。
- iOS 资料编辑页的度数与日期输入改用带符号的数字键盘。

## 验证

- 共享测试覆盖：新字段可选与旧资料兼容、正负度数、小数视力与轴位边界、日期与用药日期顺序、跨端输入元数据、历史快照保留、缺失指标处理、距离统计与低帧率说明。
- 数据仓储测试覆盖：文字报告/原始 JSON 导出、源文件不变、无额外上传、路径限制。
- Android Compose 测试覆盖：历史报告展开与两个导出入口、负数度数和中文病史显示；截图在 `feature/mine/build/reports/ui/`。
