# 无真机测试入口

项目已有逻辑单测、Robolectric Compose 交互与截图测试。Windows PowerShell 在仓库根目录运行：

```powershell
.\tools\Test-Local.ps1
```

这个命令运行 `:feature:services:testDebugUnitTest`、`:feature:fatigue:testDebugUnitTest` 并生成 Debug APK。改动后 Gradle 会重新运行受影响的任务；需要强制重跑时加 `-Fresh`。截图位于 `feature/services/build/reports/ui/` 和 `feature/fatigue/build/reports/ui/`，测试报告位于各模块的 `build/reports/tests/testDebugUnitTest/`。截图由真实 Compose 组件在本地 Android 图形环境中生成，适合检查页面布局和交互；目前测试只保存截图，没有自动像素差异断言，视觉验收仍需查看图片。

## 可选：模拟器冒烟

本机已安装 Android Emulator 37.2.12 和 Android 11（API 30）Google APIs x86_64 镜像，创建了 `EyeProject_API30`（Pixel 4）AVD。模拟器前摄使用 `emulated`；独立调试窗口可把电脑摄像头的完整画面送入 Debug 分析器。Debug APK 包含原生 x86_64 库，在模拟器上直接运行；MediaPipe 人脸关键点使用 CPU delegate，正式 ARM64 包仍使用 GPU。日常启动：

```powershell
.\tools\Start-Emulator.ps1
```

启动并运行基础冒烟测试：

```powershell
.\tools\Start-Emulator.ps1 -Test
```

`-Test` 会在测试后重新安装并打开 Debug 应用；首次打开时选择允许相机权限。只启动模拟器时，点击屏幕上的「眼健康助手」图标即可打开已安装的应用。关闭模拟器窗口即可停止；下次启动可使用快照加速。

也可先从 Android Studio 的 Device Manager 启动 `EyeProject_API30`，然后运行：

```powershell
.\tools\Test-Local.ps1 -Mode EmulatorSmoke
```

此模式要求仅有一个已启动模拟器，使用 Gradle 安装应用和测试 APK，并验证 CameraX 前摄能经过 MediaPipe 返回分析帧。它不检查眼部测量精度；实验性的视线估计 JNI 仍只构建 ARM64，在 x86_64 模拟器中会显示不可用提示。现有 `GazeNativeModelAndroidApiTest` 依赖 GPU delegate，不包含在此冒烟测试中。

## 电脑端前摄调试窗口

在仓库根目录运行：

```powershell
.\tools\Show-Camera-Feed.ps1
```

命令会启动模拟器、构建并安装最新 Debug 包、打开应用，然后在电脑上打开独立预览窗口。窗口直接采集电脑摄像头的完整画面，并把同一 JPEG 帧送入模拟器 Debug 分析器；请在模拟器中点击「开始监测」。状态栏显示实际送入帧率。窗口默认按手机前摄预览习惯水平镜像显示；取消「镜像显示」可查看模型收到的原始方向。关闭窗口会停止输入并清理调试帧。此窗口不属于 Android 应用，正式包也不读取这些帧。本机需要 Python、OpenCV、Tkinter 和 Pillow（当前环境已具备）。

电脑摄像头的有效焦距与模拟器虚拟前摄的 Camera2 参数不同，未标定时距离只是粗略估计。把尺子量得的**眼睛到电脑摄像头镜头**距离，以及同一姿势下 App 显示的距离填入调试窗口，点击「校准距离」。窗口会保存二者之比，Debug 分析器将其乘到有效焦距；校正值在下次启动时保留，仅作用于模拟器的电脑摄像头输入。请在第二个距离位置复核误差；若变更电脑摄像头、分辨率或裁切方式，需重新标定。镜头距离与眼睛到屏幕平面的距离还可能相差几厘米。

本机的 Android Emulator `webcam0` 会把电脑摄像头画面的左半边错误放大为整帧，因此 AVD 改为 `emulated`，由上面的脚本直接传入完整画面。若预览中始终看不到本人，请检查 Windows 的相机隐私权限和电脑摄像头是否正被其他程序占用。此调试输入绕过模拟器的 webcam 转换，仅用于验证后续 MediaPipe 与业务流程；CameraX 的实体摄像头输入仍需另行验证。

模拟器可把电脑摄像头作为虚拟前摄，也可以用静态图片或视频作为相机输入。用这些方式检查权限、导航、CameraX 链路和异常路径很方便，但电脑摄像头与手机前摄的焦距、视场、反光和传感器数据不同，不能据此判断距离、眨眼、角膜反光点检测的实际精度。若要重复验证算法结果，应另外使用获授权的真实采集帧和预期输出进行回放测试；回放结果仍需要少量真机样本对照。

## 可覆盖范围

| 验证内容 | 本地/模拟器 | 仍需真机 |
|---|---|---|
| 业务规则、质量拒判、页面状态和布局 | 现有单测与 Compose 测试 | 最终显示确认 |
| APK 安装、权限与页面基础运行 | 模拟器冒烟/手工操作 | 目标系统与厂商差异 |
| 前摄测距、角膜反光、光照、眨眼准确度 | 可检查流程与回放 | 实物标定和受试者验证 |
| GPU 推理与持续监测性能 | 仅作故障排查 | 目标设备实测 |

所以无设备流程可替代大多数日常改 UI、业务规则时的连接操作，无法保证医学测量效果与真机基本相同。尤其本项目 2026-09-24 的真机记录发现角膜反光有效帧为 0；模拟器通过不能解除这一阻塞。
