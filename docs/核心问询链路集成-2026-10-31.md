# 爱科核心问询链路

本次将 `agent_harness/agent/tools/ask_user.py`、`agent/graph.py` 及诊室提示词里的核心交互移植到现有应用：一次提问、等待用户、按回答追问、最后补充确认、总结退出。不是通过导入嵌套仓库或把其 `.env`、数据库打包进应用实现。

## 运行链路

Android `EyeChatContent → ChatRepository → POST /v1/chat`；iOS `AiChatPage → CloudClient → POST /v1/chat`。后端 `ChatService + InquiryPrompt` 调用已有模型端口，校验后返回 `question` 或总结。双端共用 `ChatQuestion`、`ChatEntry` 与历史截断规则。

保留原有模型供应商、知识库、登录与 AI_CHAT 同意。问询内容继续只存在手机本机；服务端沿用无会话存储的请求/响应模式。对话历史中问题及选项会作为模型上下文发送，遵循已有对话同意。

## 用户流程

1. 首页打开「AI 综合建议」，选择「帮我一步步梳理眼部不适」并发送；自然描述不适时，模型也可根据缺失信息发起提问。
2. 问题卡提供简短选项，点击选项填入输入框；用户也可直接输入，点发送继续。不会自动替用户选择或作答。
3. 同一时刻只有最后一条助手消息的问题可操作。下一条用户消息回答或作废旧问题；换话题不会被前端强制拦截。
4. 信息足够后问「还有没有其他需要补充的？」，选项严格只有「没有」，同时允许自由补充。
5. 收到确认后给出「综合判断、就医建议、就医前的缓解与注意事项、需要警惕的信号、复诊与跟进」五段总结。可再次发起问询，也可发送「结束问询」。
6. 命中已有危险信号规则时，回答必须明确建议尽快到医院眼科，且服务端校验不允许再返回问题，问询随之中止（不依赖模型决定是否继续）；界面在提问下方另有醒目的就医提示。

## 验证与发布边界

共享协议测试覆盖旧记录兼容、问题恢复与用户伪造元数据清理；后端 API 测试覆盖追问、确认、总结、退出和非法问题；Android 测试覆盖问题持久化及选项待确认交互；iOS 共用 CloudClient 对接 Ktor 测试服务器验证问询、重启恢复与总结。

模型采用脚本替身，真实模型问询质量需另外实测。Windows 可以运行共享 JVM、后端和 Android 测试；Swift/Xcode 编译仍需 macOS 或云编译。

服务端和客户端须同时升级。新增字段有默认值，旧客户端保持普通对话；新客户端连接旧后端时仍只有普通对话。此阶段不包含后台监测自动发起问询、定时回访、完整 LangGraph/Web 服务接入或线上后端部署。
