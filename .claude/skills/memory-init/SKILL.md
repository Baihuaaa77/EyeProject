# auto memory 初始化与检查

## 第零步：确认记忆功能已开启（闸门，不过就停）

判断依据（满足任一即视为已开启）：

1. 本会话系统配置中挂载了持久记忆目录（system prompt 含 Memory 段并给出记忆根目录）
2. settings（`settings.local.json` / `settings.json`）中配置了 `autoMemoryDirectory`
3. 该记忆目录在磁盘上真实存在

- **三者都不满足** → 视为未开启：**停在这里**，告知用户开启方式（在 `.claude/settings.local.json` 配置 `"autoMemoryDirectory": "<绝对路径>"` 后重启会话），**不要往下执行任何步骤**。
- 仅依据 2/3 成立、本会话未挂载 → 可继续执行，但汇报中提醒「本会话的自动加载可能未生效，重启会话后恢复」。

## 第一步：盘点现有记忆（只读，绝不直接覆盖）

1. 列出记忆目录全部文件
2. 通读 MEMORY.md 与所有记忆子文件
3. `wc -l -c` 统计 MEMORY.md 与各文件的行数、字节数

## 第二步：写入整理纪律（长期规则，幂等）

检查是否已存在纪律文件（约定名 `memory-discipline.md`，type: feedback）：

- **已存在** → 核对内容与下方 7 条一致，缺失或走样处用 Edit 原地补齐，不新建第二份
- **不存在** → 新建，frontmatter `type: feedback`，正文为 7 条 + Why + How to apply

纪律 7 条（措辞保持原样维护）：

1. MEMORY.md 只做索引，每个主题一行，不在索引里堆放正文
2. 以 150 行或 20KB 为日常软上限，永远不要逼近 200 行 / 25KB 的加载上限
3. 每个子文件只保留一个明确主题
4. 写入前先检索现有记忆；能够更新旧记录就不要重复新增
5. 新结论推翻旧结论时，直接修正旧记录，不要保留互相矛盾的两个版本
6. git 代码和项目文档中明确存在并且容易重新获得的内容，不要重复抄进记忆
7. 如果当前实现支持记忆类型，则按照 user、feedback、project、reference 分类，不要为了分类而创建空目录

## 第三步：索引与初始化

- MEMORY.md 不存在 → 新建：一行标题 + 每个记忆文件一行索引（含 discipline 自身）
- MEMORY.md 已存在 → 只**补缺失的索引行**，不重写既有行、不动正文
- 已有记忆文件保持原样；发现的重复 / 冲突 / 过时**不在本 skill 处理**，提示用户跑 `/memory-maintain`（职责分离：init 只建骨架，maintain 才动手清理）

## 第四步：幂等出口

MEMORY.md 与纪律文件都已存在且格式正确 → 报告「记忆库已初始化，无需变动」+ 现状统计，**不做任何写入**。

## 汇报格式（固定四段）

1. 当前记忆目录路径与文件清单
2. 创建或修改了哪些文件（本次实际动作，无动作则明说）
3. MEMORY.md 当前行数和大小
4. 发现的重复、冲突或潜在风险（空库初始化则写「全新初始化，无既有风险」）
