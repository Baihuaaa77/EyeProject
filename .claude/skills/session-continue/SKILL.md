# 会话续接：从 auto memory 恢复上下文

## 执行步骤

1. **定位**：读记忆目录的 `MEMORY.md`（记忆目录由 settings 的 `autoMemoryDirectory` 指定，当前为项目根 `memory/`）。
   - 用户给了关键词 → 按关键词匹配索引条目
   - 没给关键词 → 选记忆中标记为「进行中 / 待办」且最近更新的任务
   - **多个候选任务分不清哪个是本意时，先列出来问用户，不要猜**
   - MEMORY.md 不存在或为空 → 明说记忆库为空，向用户要上下文
2. **读取**：只读与当前任务直接相关的记忆子文件；文中引用的其他记忆按需展开。
3. **核实**：记忆中提到的文件路径、配置、命令在动手前先确认仍然存在——记忆反映的是写入时刻的状态，仓库可能已经变了（不一致时以仓库现状为准）。
4. **汇报（先于动手）**，固定格式：
   - 当前进度 + 已确认的关键决定 + 下一步行动，**两三句话**说清
   - 注明信息来自哪些记忆文件（文件名）
   - 记忆中没有记录的部分**明确说「没有记录」**，不根据印象猜测、不脑补
5. **继续**：汇报完直接执行下一步行动。若下一步是破坏性操作、或需要用户先提供输入（如连设备、做选择），先停下来要确认。

## 边界

- 记忆与仓库 / 文档现状冲突时，以仓库为准，并按纪律第 5 条顺手修正记忆
- 记忆缺失到无法确定任务范围时，向用户要上下文，而不是开始猜测性的工作
