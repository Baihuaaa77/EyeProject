# 光码映光独立实验 v0.8.0

独立iPhone验证应用。包含原生像素眼区、手动曝光、快速明暗码、全部错码对照、亮灭审计和实验清单导入。研究原型，需真机确认光学来源。

## v0.8：白点、真实灭灯与时序核查

新采集只保留明暗编码白点、常亮白点、全黑阴性对照。已移除圆环/十字图案及其模板匹配；移动点、白屏黑点也不再提供。旧枚举和图案尺寸字段仅用于读回历史实验，旧视频复算时按亮斑跟踪，不声称识别图案结构。

- 三种编码：平衡伪随机明灭、曼彻斯特双相（每码元交换亮灭）、稀疏短脉冲（正码元前35%发光，整体约17.5%占空比）。新采集默认0%灭灯/100%亮灯，码元可选500/250/125ms，总时长32秒；常亮对照可匹配编码时间均值。实际每显示帧的强度、参考码、回调时间、屏幕亮度和白点中心都保留，不能只按名义码元猜测半码切换。
- “贴近前摄”把完整圆点的上缘放在顶部安全区下方2pt；随着圆点大小调整中心，不再固定在屏高15%处。位置受刘海/灵动岛安全区限制；实际中心和承载尺寸写入显示日志。
- 数字键盘增加“收起键盘”；滚动可收起；准备相机和开始测试前强制结束各窗口的输入焦点，离开设置阶段也取消焦点。
- 系统屏幕亮度滑条和“设为100%”立即写入`UIScreen.brightness`，通知与4Hz读回监控显示实际百分比；开始前核对读回值。系统手动调整会同步设置页，采集时保留目标/读回差异。停止实验不降低亮度，离开应用后恢复原值。`brightness_log.json`与显示逐帧亮度一并进入单JSON导出。百分比是系统属性，不是实测nit；不能据此证明热限亮、自动亮度及面板光输出恒定。[Apple亮度属性](https://developer.apple.com/documentation/uikit/uiscreen/brightness)、[变化通知](https://developer.apple.com/documentation/uikit/uiscreen/brightnessdidchangenotification)。

### 本轮六次真机录像的开发复核

2026-11-16第二批包含四段约32秒录像和两段提前停止录像。历史编码轮低电平为5%，并非完全灭灯；显示日志中系统亮度读回为100%，与用户手动设置一致，不能证明旧版控制已有效。

视觉回看发现环境/窗面反光、低电平时的纹理峰，以及图案中心和外圈在小尺度下混合。训练时亮暗样本数不相等，旧版未按数量分别归一会偏向恒定反光；新版平衡两类权重，只在两类均存在时建立编码身份。新版另执行图像独立跟踪与亮灭约束跟踪，稳定低电平/灭灯不更新测量身份，保留独立候选供调查。切换、曝光与延迟不确定区间单列，不强行作阴性。

同一H.264解码像素上，最新64pt白点录像左/右眼低电平图像独立测量为1/6帧；约束后均不计测量，这是规则抑制，**不是人工证实7次误检**。8个清晰白点的代理无叠加图近似标注（约±2px）显示，新旧位置基本相同，新版误差中位数约0.57px，仍有一个右眼样本约5.38px偏差。模糊右眼帧未强制标注，不能据此报告整体准确率。图案录像多数只得到弱观测，尚不能证明身份正确；移除图案后仍需用新白点/真实灭灯实测。

这批资料用于开发和反复回看，不是独立验证集。私人原视频、盲查图、标注、新旧逐帧输出、暗段核查与合并数据只保存在本地忽略目录；不进入Git或CI。

## 逐帧检测与时序关联

新轮次在录像结束后读取相机原生BGRA眼区，执行与便携Swift复算工具相同的算法。额外分析不放进相机采集回调。原128×64空间/码算法仍保留为历史对照；屏幕矩形与暗孔轮继续走结构分析。

1. MediaPipe确定虹膜中心、完整半径与眼睑。搜索完整虹膜**面积60%**对应的中心椭圆与眼睑多边形的交集：半径比例为`sqrt(0.60)≈0.7746`，不是半径60%。物理尺寸估计始终使用完整虹膜直径。
2. 原生像素多尺度中心－周边差分找局部峰，局部噪声估计信噪比；连通亮斑给出加权亚像素中心、轴比和半高等效直径。形态与光学预计尺寸使用软评分，小于2个旧分析网格像素不再直接拒绝。
3. 前8秒稀疏帧在虹膜相对坐标内聚类，建立持续光点的身份和外观参考。光码轮分别按训练段正负样本数归一，使用亮暗均值差抑制恒定环境反光；运动轮参考固定白点及三个外围光源的相对布局，允许成像方向及尺度误差。存在上方固定白点的软先验，搜索区域不因此裁小；这些先验针对本实验刺激布局。
4. 单帧关联综合虹膜位移/尺度、局部外观相似度、亮度、形态与候选歧义。用光点外围纹理的归一化相关配准补偿手机微晃，中心光点不参与配准，降低光码变暗的干扰。关键点突然跳动时限制预测位移。
5. 同时从前向后、从后向前关联。一致时融合坐标；明显分歧降为预测并降低质量分，避免光点暗下时跳到环境反光。短时缺失用邻帧支持的位置，长时缺失质量分归零；每个相机交付帧都保留记录。没有任何眼区证据时坐标可为空，不制造图像观测。
6. 输出相机原生像素坐标、图像测量坐标、虹膜相对位置、质量分、状态、信噪比、歧义、位置不确定度及实测/预计斑径。状态为图像观测、弱观测、短时预测、无可靠观测。质量分未经概率校准，坐标覆盖率不等于检出率；图像映光坐标也不是已标定的屏幕注视点。
7. 先进行不受当前亮灭门控的完整图像跟踪；前半段相关≥0.6且拟合延迟在0–150ms内时用于曝光窗口判定，否则使用整个0–150ms保守延迟范围。结合曝光时长、半帧及显示容差，只有整个窗口同状态才算稳定亮/低电平/灭灯；暗段保留预测且质量分≤0.2，不更新测量身份。亮灯帧有当前真实峰且前后各有邻帧支持时，才可增强为弱观测；不会把平坦图像补成测量。
8. 编码验证始终读取门控前的独立图像信号，保留`independent*`字段、候选、时序类别及抑制标志；不使用门控信号抬高相关。光码仅用前半段拟合延迟，后半段计算固定参考及63个错位码的相关。门槛为训练r≥0.35、后段r≥0.30且比最大错码|r|高0.15。单帧关联不根据当前码元挑峰；训练期光码参与建立身份，因此训练相关不能单独作为证据。光码时间一致也不单独证明角膜来源。

旧记录可在结果页点“用原视频逐帧重新分析”。复算使用原视频解码眼区，记录H.264压缩来源；保留`summary_before_tracking.json`、旧检测字段与原始视频，另存`glint_tracks.json`、新全画面叠加视频和眼区叠加PNG。播放中可查看坐标、状态和质量分；实线圆为图像测量，虚线为预测/无可靠观测，低电平/灭灯预测用叉号并标记时序类别。

### v0.7历史两段录像复核（旧80%半径版本）

2026-11-16本地复核两段各959帧、约30fps录像，分别为光码轮与多白点运动轮。旧128×64采样会将光码反射压到约1.5像素、运动探针压到约0.8像素；相邻关键点位移P95约7–8个原生像素，固定网格位置与形状硬门槛容易丢点。

改为80%搜索与原生双向跟踪后，每眼每轮均输出959条坐标及质量记录。光码轮后半段相关约0.932/0.901，最大错码|r|约0.421/0.424；目视抽查10个可见光点误差约0.2–1.3px，6个暗点样本未标成图像观测。运动轮14个可见样本仍有约0.5–5.2px误差，近邻白点融合和身份歧义仍需改进，不能声称逐帧位置都已准确。

上述是用于开发的同两段视频回看，目视标注由代理读取无叠加裁剪图完成，约2–3px标注不确定度，并非专家金标准或独立人群测试。后半段在程序内不参与身份/延迟拟合，但开发中已被回看，不应把结果当作无偏的外部验证。私人视频、图像、标注与逐帧结果只保存在本地忽略目录，不进入仓库或CI。

## 自动距离与光学尺寸核查

- 新轮次调用主 App 共用 `DepthFromIris` 自动测距，优先相机帧内参，缺失时按当前格式视场角回退；测距未稳定不能开始。每个眼区的逐帧记录保留距离、焦距和来源，结果使用有效帧距离中位数。不同 App 沙盒不会共享个人测距校正系数。
- 屏幕毫米尺寸由原生分辨率及已知 PPI 规格映射估算，未知机型明确标记460 PPI假设；保留来源。亮点毫米直径＝屏幕宽毫米×亮点pt/屏幕宽pt。
- 以角膜前表面球面半径 R=7.8mm 作为群体假设、虹膜直径11.7mm作为像素尺度，近轴凸面镜缩率 `m=(R/2)/(d+R/2)`，预计反射直径 `D_px=D_mm*m*iris_px/11.7`。前摄图像不能单独辨识个人曲率，不能把假设曲率标为实测。
- 同时显示距离变化与曲率±0.6mm敏感性范围、候选等效原生像素直径及比值。范围不是置信区间，也不直接作为检出门槛；未包含失焦、离轴、ISP与屏幕/镜头位置差。
- 模型参考：[角膜凸面镜成像研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC3016080/)、[角膜曲率与反射结构研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC2795748/)，屏幕规格示例：[Apple iPhone 16 Pro](https://support.apple.com/en-us/121031)。

## 搜索范围与采集性能

- 新实验与原生跟踪复算统一使用60%虹膜面积（半径约77.46%）与可见眼睑多边形的交集。主 App 原75%搜索参数及疾病规则保留；旧空间算法仍按保存范围复算。
- 虹膜较大时扩大原生裁剪窗，128×64分析网格等比采样；原生BGRA眼区PNG仍无损保存。每帧ROI公开原生像素/分析像素比例，不能把采样或放大当作新增分辨率。
- 准备页改用原生预览层；取消UIImage逐帧转换及原约3fps的预览限制。只节流诊断文字，不限制预览。准备阶段跳过眼区像素提取；关键点推理输入最长边1280，录像及光学计算继续使用采集原图；移除重复Kotlin光学计算及常规窗口的双线性插值。
- 状态显示实际交付帧率、分析耗时、GPU/CPU；`camera.json`保留处理耗时与相机/编码丢帧。FPS为交付回调统计，不代表已经测得持续满帧，仍需真机比较。

## 查看与独立导出

- 原视频支持1–12倍双指缩放、拖动、双击、缩放按钮和全屏查看；播放控制在缩放区外。叠加开关及缩放保持同一AVPlayer，不切换视频源、不重置时间。
- 播放叠加和全画面派生视频共用同一坐标变换；旧检测只显示有效且距画面不超过120ms的记录，新跟踪按视频PTS选取80ms内的逐帧记录并明确预测状态。可单独分享原视频、全画面可视化视频、每眼放大PNG、每眼叠加PNG及眼区视频。眼区图默认小预览，点开可缩放。
- “导出全部数据”生成单个`实验数据_完整.json`：合并全部JSON（含逐帧跟踪）与帧JSONL，并以Base64内嵌原128×64灰度/RGB分析像素，可恢复旧版空间复算；原生跟踪复算另需原视频。流式编码避免一次持有完整像素字符串；视频和图片通过各自按钮分享。
- “导出轻量数据”生成单个`实验数据_轻量.json`，含全部结构化结果和日志，不含二进制像素。完整文件体积较大时可选轻量版本。
- 还原：`python tools/unpack_bundle.py 实验数据_完整.json 新输出目录`，然后运行`corneal-replay 新输出目录 新结果.json`；还原不会覆盖已有目录。视频另行保存，不内嵌进JSON。
- 原生复算：安装`tools/requirements-replay.txt`；执行`python tools/prepare_native_replay.py 实验目录 新原生像素目录`，再运行`corneal-replay --track-native 实验目录 新原生像素目录 新跟踪结果.json`。`python tools/review_glint_tracking.py 实验目录 新跟踪结果.json 新复核目录`导出对照图、逐帧CSV与分状态统计；默认像素目录为实验目录中的`native-replay`。不得用统计中的坐标条数冒充准确检出数。

## 构建

GitHub Actions入口：`.github/workflows/corneal-code-lab.yml`。先做工程清单与Swift语法预检、便携算法/Python回归，再用XcodeGen与CocoaPods构建模拟器测试和未签名真机IPA。

本目录执行：`swift test -c release`、`python3 -B -m unittest discover -s tools -p "test_*.py"`。

KMP、MediaPipe配置及模型沿用本次分支的共用核心；实验使用的私人记录和视频不纳入仓库。

本次针对既往失败保留修复：断言按实际开放模式和图层契约检查；合成录像按编码后解码像素比较，不把H.264误差当算法差异；复杂数值表达式拆成显式类型与循环；编码器就绪等待上限30秒。CI在模拟器测试前明确启动设备并等待bootstatus，避免冷启动竞争。Windows本地只能验证便携算法、Python与Swift语法；UIKit/SwiftUI类型检查、模拟器录像和真机归档由macOS流水线实际验证，不能以语法预检冒充构建成功。
