# 光码角膜映光真机验证

独立 iPhone App，Bundle ID `com.zkyjss.cornealcodelab`，最低 iOS 16。界面和采集独立于主 App，但直接链接主 App 的 MediaPipeTasksVision 1.0.0、同一 face_landmarker.task、EyeCamera 检测配置/灰度适配器和 KMP EyeScreening 共用核心；无服务器依赖。实验样式令牌集中于 `core/designsystem/ios/CornealLabStyle.swift`；亮点灰度属于实验刺激。

## 目标与依据

依据用户提供《方向二-光码遮盖.pptx》第 3–5、8–9、11 页，先验证：①黑屏单白点是否可在普通前摄形成可检查亮点；②已知编码是否有助于从固定反光中找出屏幕响应；③同等条件下定位可靠性是否改善。PPT 中的收益是待验证假设。本程序不输出斜视诊断或棱镜度，不改变主 App 的测量规则。

ScreenGlint 提供屏幕反射作为眼动线索的已有研究，不能据此认定本程序的小白点、编码或临床筛查已有效。

## v3 检测链路与本轮修正

1. 与主 App 同一 MediaPipe 模型和 SDK，眼睑/虹膜关键点经同一 `LandmarkGeometry.face` 转成像素坐标；`EyeOpticalAlgorithm.measure` 直接在原分辨率彩色帧的相同 RGB 灰度上执行，不写 Swift 仿制版。
2. 基础映光候选是主 App 的灰度阈值、小高亮连通域、面积/对比度与中心距离筛选结果。深色圆形区域按主 App 的虹膜关键点定位，不再使用 Apple Vision 或另行扫描巩膜边缘。它仍是模型估计，不是已标注验证的像素级分割。
3. 编码为新增的第二阶段：在同一虹膜内区中，用局部高通信号做明暗相关或多峰轨迹/颜色匹配。为检查弱反光，它可以保留未达到主 App 基础高亮阈值的候选；结果和基础候选分开显示，不能称为两种算法完全相同。
4. 修复 SwiftUI 重建刺激视图时只迁移静态层、运动层滞留旧视图的问题；所有层共同重挂载并测试多时刻位置变化。固定点和移动点直径分别可设置，取消固定点写死24pt。
5. 删除“全白常亮（找点）”模式，保留旧记录读取：旧 peak 记录按恒亮100%解释；旧运动记录仍保留24pt固定点和当时的移动点大小。
6. 结束后提供相机原生BGRA眼区的无损PNG图、叠加图、640×320彩色眼区原内容视频和叠加视频；全画面原始camera.mov始终保留。视频只裁剪放大并重新编码，不增加传感器分辨率。

## 实验条件

| 条件 | 屏幕内容 | 用途 |
|---|---|---|
| 常亮白点（均值对照） | 黑底、恒亮白点，匹配明暗码的输出均值 | 与明暗码配对比较 |
| 明暗编码白点 | 同一位置，64 个平衡伪随机码元，0.5 秒/码元 | 时序相关定位 |
| 固定注视＋移动光点 | 恒定、尺寸可设置的白色注视点；外围 1–3 个恒亮移动光点 | 空间轨迹解调 |
| 全黑阴性对照 | 无实验光点 | 排查环境光与系统隐私灯反射 |

明暗档位：弱 65%/95%（旧版）、中 20%/100%、强 5%/100%（新版默认）、全幅 0%/100%。均值对照分别为 80%、60%、52.5%、50%。点直径 16/32/64/96 pt，默认 64 pt、屏幕亮度 100%。百分比是通道值，不是物理光强。保留旧轮次配置和读取兼容。

运动轮**始终盯着不动的小白点**，不要追随外围光点。外围分区为左下、右下、右上，轨迹使用不同伪随机相位并平滑过渡；可选全白，或依次红、绿、蓝。位移范围有小/标准/大三档；实际显示位置按屏幕尺寸和系统安全区限制并逐显示帧保存。固定注视点不参加运动解调，也不会闪烁。运动轮恒亮预适应时外围点停在初始位置，锁定曝光后开始移动。

每轮 32 秒，前置 2.5 秒预适应；无相机预览或文字覆盖刺激。点屏幕任意位置停止，结束恢复原屏幕亮度。

系统亮度比例不是 nits，RGB 灰度不是线性光强。iOS 相机隐私指示灯无法由 App 移除，也可能形成反光；全黑对照保留这一混杂因素。编码不能恢复原本弱到噪声以下的光学信号，也不能单独区分角膜和镜片反射。

## 首次手机验证

1. 用 Sideloadly / 现有个人 Apple ID 签名方式安装 `CornealCodeLab-unsigned.ipa`；它是独立 App，可与眼健康助手并存。未签名 IPA 不能直接点开安装。
2. 成人、手机固定、普通室内、约 33 cm、不戴框架镜起步。关闭夜览、原彩和改变颜色/亮度的辅助设置并记下条件。自报距离仅是条件记录，不是自动标定。
3. 点「准备相机」，确认双眼清晰。首轮关闭「沿用上一轮锁定曝光」，选择均值常亮、64 pt，再点准备相机并开始。
4. 只看白点，可自然眨眼。采集后人工检查原视频中的亮点是否确实位于角膜；不要只看圈或热图。
5. 保持距离、大小和环境，先比较编码与均值对照；另做运动轮，先 1 个白点，再 2–3 个白点与彩色点，保持注视点位置不变。相同位置、大小、距离、光照、屏幕亮度，开启「沿用上一轮锁定曝光」，做编码和全黑各一轮。每次先点准备相机。相机会保留上轮锁定参数，仍须用 camera.json 和逐帧日志核对曝光/ISO 未变。
6. 点「导出本轮」保存全部文件。也可在「文件 → 我的 iPhone → 光码映光验证 → CornealCodeLab」里压缩某轮文件夹后导出。

初版限成人短时台架；出现不适立即停止。不把低码率或小白点当作光敏安全认证，暂不招募儿童。原视频含面部，只保存在本机，用户主动分享才会导出。

## 实验矩阵与判定

先做最小矩阵，再一次只改变一个因素；不要只挑成功视频。

| 阶段 | 因素 | 重复 |
|---|---|---|
| 1 | 64 pt、33 cm、普通光、无镜；均值常亮/强编码/全黑 | 各 3 轮，交替顺序 |
| 2 | 白点 16/64/96 pt，其余固定 | 常亮/编码各 3 轮 |
| 3 | 距离 25/40 cm、暗室/普通光/背窗、无镜/框架镜 | 分别改变，先各 3 轮 |
| 4 | 固定注视：1 个白色移动点、3 个白点、3 个彩色点；增加一轮故意追随移动点的混杂对照 | 各 3 轮 |
| 5 | 外置点光源、屏幕全黑的阳性对照 | 3 轮，确认前摄能拍到已知映光 |

96 pt 仍不可见时，先查曝光、距离、原始分辨率和阳性对照，再判断该机型/条件不可用。全黑时无注视点，尽量保持上一轮视线；它仅检查光源来源，不比较眼位幅度。

主要指标：有效眼区覆盖率、人工确认角膜映光的检出率、非角膜假候选比例、后半段编码响应、位置抖动、对人工参考点的眼区像素误差。单帧亮点候选率不是映光检出率，绿圈数也不是准确率。完整轮次才进入配对比较；提前停止、无视频、曝光变化、日志不完整等单列失败，不删除。机型、曝光、光照、距离或点大小不同则不合并比较。

## 实现与证据边界

- 前摄彩色视频优先 1080p、请求 30 FPS，未镜像、纵向。视频保留交付帧；MediaPipe 每两帧分析一次。实际 FPS、交付/写入丢帧、曝光和 ISO 均记录。
- MediaPipe 估计人脸、眼睑及虹膜关键点；无已验证角膜/虹膜分割。要求单人、正面、眼宽≥20 像素、睁眼，闭眼、裁切、大幅移动和过曝单列原因。
- 眼区按未镜像画面 x 排序为 image_left / image_right，不宣称解剖左右。按 MediaPipe 虹膜中心配准成 128×64 双线性采样区；不会凭空增加相机光学分辨率。运动轮另存 RGB 通道。
- 搜索区域与主 App 共用算法相同，半径为 MediaPipe 虹膜半径的75%；编码候选额外与眼睑轮廓取交集。虹膜直径不足12个原始相机像素、关键点缺失、闭眼、头动等帧排除。没有关键点时不回退到整眼/眼角搜索。
- 基础单帧法直接使用主 App 共用光学算法的高亮连通域结果；编码阶段另取局部高通峰；两者都可能来自镜片反光。
- 编码法先做局部高通以减轻全脸亮度变化。仅前 16 秒选位置和 −100…300 ms 延迟；后 16 秒固定位置/延迟独立验证。另与 4 个错位参考码对照。常亮、全黑也做伪码分析，但永远不宣称发出了编码。
- 参考门槛：训练 r≥0.35、验证 r≥0.30、验证比最大错码绝对相关至少高 0.15、响应幅度≥0.5 灰度级。这是未经真实标注校准的工程规则；像素/延迟搜索存在多重比较，错码对照不是正式统计显著性检验。
- 绿圈仅表示可复现编码响应候选，仍可能在镜片；橙圈是未通过独立验证的聚合候选。必须用彩色视频人工确认其在角膜上。热图总有最高点，不等于成功。
- 运动法：各通道局部高通、多峰亚像素质心、仅按邻近距离关联轨迹。建轨迹时不使用已知屏幕运动，避免按答案拼点。白色用灰度，彩色用目标通道减其余两通道均值；颜色是辅助通道，不能保证物理光谱分离。
- 只用前16秒选轨迹、−67…267 ms延迟与二维线性映射，模型包含瞳孔相对眼睑中心及人脸框平移四个干扰项；后16秒固定模型。用相对仅含干扰项基线的误差下降比例评估，并比较4个循环错位轨迹。工程门槛：训练增益≥0.45、验证增益≥0.30、验证比错轨迹高0.20、源运动RMS≥0.18采样像素、有效眼区中的轨迹覆盖≥60%。
- 如果眼动/头动干扰项可解释超过85%的刺激轨迹，或缺少干扰记录，标记混杂不通过。它不是完整的眼动/头姿标定，无法消除所有运动伪影。固定注视和台架仍然必要。所有统计门槛均未临床验证，错轨迹不是正式多重比较检验。
- 多点可视化分别显示观测和固定模型预测的X/Y曲线，同一像素尺度；不分别缩放成视觉吻合。圈对应第一条轨迹末帧的参考眼区，逐光源结果以列表为准。没有稳定轨迹时不画假圈。
- 相机 PTS 转换到 host clock；显示记录 CADisplayLink 的计划合成时间与 host-clock 偏移。没有光电二极管校准，延迟包含屏幕、ISP、曝光、滚动快门影响，不能称为硬同步或纯硬件延迟。
- 该实验只支持当前机型、当前条件的初步光学可行性，不能外推斜视诊断精度。

## 导出文件

| 文件 | 内容 |
|---|---|
| camera.mov | 高码率 H.264 原始彩色视频，无分析叠加；不是传感器 RAW |
| camera.json | 系统/相机参数、曝光锁定、实际 FPS、视频起始 PTS、丢帧及写入状态 |
| display_events.json | 明暗轮每码元、运动轮每显示帧的计划 host 时间和各光源 id/颜色/归一化位置；另存、实际灰度、参考码、回调时刻、系统亮度；对照轮参考码只作伪码分析 |
| frames.jsonl | 帧索引、PTS、host 时间、ISO/曝光、质量原因、ROI、虹膜搜索区、眼睑轮廓、瞳孔估计、运动干扰项、单帧候选、饱和度、二进制偏移 |
| patches.f32 | little-endian Float32，每眼区 128×64（旧版64×32），按 patchOffset 定位，未高通灰度 |
| patches_rgb.u8 | 仅运动轮，交错 UInt8 RGB，按 rgbPatchOffset 读取 |
| image_left/right.png | 128×64灰度分析采样图（保留兼容） |
| image_left/right_original.png | 与参考时间对应的相机原生BGRA眼区，无视频压缩、无损PNG、无检测叠加 |
| image_left/right_overlay.png | 在相同彩色眼区上的640×320放大叠加图 |
| image_left/right_original.mov | 彩色眼区原内容，裁剪放大至640×320、H.264派生 |
| image_left/right_overlay.mov | 相同时间轴上的检测叠加视频 |
| native_snapshots.json | 原生PNG的时间、原生/分析ROI及尺寸；临时像素缓存导出完成后删除 |
| eye_media.json | 派生帧数、裁剪和参考时间差说明 |
| summary.json | 实验条件、完整性提示、结果、热图、信号与参考码 |

运行 `python experiments/CornealCodeLab/tools/review.py <某轮或多轮父目录> --output review.html`，生成离线审阅与标注页。明暗轮直接从原始灰度重算固定候选的后半段相关；运动轮在原始灰度/RGB中复取已选轨迹附近的峰，固定前半段模型复算后半段误差与错轨迹。离线复核不重新关联轨迹，也不证明角膜来源。点选人工参考映光后，可导出标注 CSV。误差单位是重采样眼区像素，不能直接当角膜毫米误差。

## 云编译

工作流 `.github/workflows/corneal-code-lab.yml` 用 XcodeGen/CocoaPods 生成独立工作区，Gradle构建主 App 共用KMP核心，运行明暗/运动/错轨迹/追视混杂/静态灯/多色峰/虹膜范围/旧数据兼容测试、主 App 共用光学结果、模型加载、视图重挂载/移动/尺寸、彩色裁剪方向/逐帧视频以及原生准备页渲染，再构建未签名真机包；artifact 为 `corneal-code-lab-unsigned-ipa`。模拟器不验证真实屏幕映光。
