# 老视与斜视评估模型原型

手机端完成测试后，`ScreeningAssessmentModel` 在本机给出低／中／高初步风险等级，或因质量不足输出“无法评估”；同时把质量状态、适用范围、提示类别、结构化特征和原因写入会话 JSON 的 `assessment` 字段。`screening_model.py` 使用这些特征以及后来取得的临床标签，分别训练老视与斜视的逻辑回归基线模型。两者版本必须匹配。本目录的训练代码无需第三方 Python 包。

## 当前可运行的结果

- 老视：先检查屏幕与距离标定、右眼／左眼／双眼近视力题数、重复近点和远近切换数据；合格后给出近点、近视力及近距切换的探索性提示。日常近用矫正模式只描述实际视觉表现，不解释为残余调节能力。
- 斜视：先检查相机标定、有效帧比例、至少 3 秒连续固定注视、遮盖解除事件和跟随数据；合格后报告双眼瞳孔—反光候选点差、再注视位移和追随相关。工程异常门槛仅用于提示复核，不能换算棱镜度或作为斜视诊断阈值。
- 任一关键任务缺失时输出“无法评估，请复测”，不强行给出低风险或阴性结果。`research-rules-2` 是确定性的工程基线，不是由临床病例学习得到的模型。

## 当前风险分级规则

分级是在数据质量合格后才执行的**原型工程规则**。资料支持综合观察这些测试项目，但下述数字切点尚未经过本设备或临床队列验证，不是文献给出的通用诊断界值。

| 病种 | 中风险触发 | 高风险触发 | 低风险含义 |
|---|---|---|---|
| 老视 | 近点中位数 ≥40 cm；或 40 cm 任一眼别未通过 0.5 等级；或 25 cm 正确率 <50% 且 50 cm 正确率 ≥75%，三者之一 | 上述至少两项 | 完整测试中三项均未触发；不能排除老视。日常近用矫正模式只评估当前矫正条件下的近距离功能受限。 |
| 斜视 | 固定注视稳定水平光学差 ≥0.15 虹膜直径；或至少两次解除遮盖后再注视位移 ≥max(0.12 虹膜直径，固定注视噪声的 3 倍)；或追随速度相关 <0.3 | 固定注视差与遮盖再注视两项同时触发 | 完整测试中三项均未触发；不能排除间歇性、小角度或垂直斜视。 |

斜视规则仅针对近距离水平眼位及眼动异常。屏幕白点不是经过临床标定的同轴点光源；角膜反光候选、头姿和个体视轴偏心都可能造成假阳性或假阴性。高风险提示建议专科复核，不换算棱镜度。低风险表示“本次未触发预设条件”，不是确诊阴性或经验证的低患病概率。

## 使用真实临床标签训练

准备一个仅含同一病种的会话 JSON 目录，以及 CSV：

```csv
session,subject_id,label
presbyopia_123.json,P001,1
presbyopia_456.json,P002,0
```

`subject_id` 是脱敏后的受试者标识；同一人的多次测试必须使用同一个值。`label` 为临床方案最终定义的 0/1 金标准，不能填手机端的探索性评估结果。老视应由专家明确远用矫正下的调节功能异常或临床老视标签；斜视可由临床遮盖及三棱镜检查定义目标病种。两类任务分别准备标签表，不要混用。

```powershell
python -m unittest discover -s backend -p 'test_*.py'
python backend/screening_model.py train --kind PRESBYOPIA --sessions data/presbyopia --labels data/presbyopia_labels.csv --out data/presbyopia_model.json
python backend/screening_model.py predict --model data/presbyopia_model.json --session data/presbyopia/presbyopia_123.json
```

斜视用 `--kind STRABISMUS` 另训一个模型。程序要求每类至少 5 位受试者，只接受质量合格且版本匹配的会话；按受试者而不是按帧或测试划分留出集。预处理参数仅从训练集估计，缺失值显式编码。输出包含留出集混淆矩阵、敏感度和特异度。这个最小样本限制只为程序能运行，不代表临床验证充分。

`predict` 输出的是**未校准的研究分数**。0.5 只是软件演示切点；手机端低／中／高来自上面的规则，与离线逻辑回归分数无关。在获得足够独立临床样本并确认金标准、患病率、跨设备表现和阈值之前，不把此分数或三级类别作为诊断概率。模型不会自动下发到 Android；手机端继续显示透明的规则基线。临床试验阶段应另做受试者级交叉验证、独立外部验证、概率校准、按年龄与设备分层评价，并锁定模型后再评估推广。

## 判读依据与边界

原始需求文档：`docs/智能眼科-整合9.18.docx`，研究内容二、三。文档提出多指标融合、临床标签训练与三棱镜遮盖检查对照，但尚未提供可训练病例、个体设备光源几何标定、经过验证的归一化瞳孔反光阈值或年龄常模。

- [AAO EyeWiki：Presbyopia](https://eyewiki.aao.org/Presbyopia) 指出需结合矫正近视力、屈光状态和近用需求解释表现。
- [主观移近法与客观调节测量的比较](https://pubmed.ncbi.nlm.nih.gov/15210220/) 发现移近法可高估客观调节幅度，因此本原型只报近点及近似调节需求。
- [AAPOS：斜视测量](https://www.aapos.org/glossary/strabismus-measurements) 将角膜反光、遮盖与棱镜检查区分，且说明反光位置可受生理视轴差影响。
- [手机眼位测量初步研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC6369861/) 使用专门的光源和拍摄协议；本项目屏幕白点形成的反光仍待验证。
- [照片 Hirschberg 与三棱镜遮盖比较](https://pubmed.ncbi.nlm.nih.gov/34851974/) 显示两者并不能直接互换，因此当前不使用文档中的 10△、5△、6△作为手机数据门槛。

代码中的 0.15／0.12 虹膜直径、相关性 0.3、近视力 0.5 等值只为运行工程原型，均需用临床数据重新确定。当前斜视结果不区分内斜、外斜、垂直斜视或隐斜的诊断类别。
