# 干眼、老视与斜视评估模型原型

手机端完成测试后，共享核心（`shared/screening`）在本机按确定性规则给出低／中／高初步风险等级，或因质量不足输出“无法评估”（`UNKNOWN`），并把质量状态、规则版本和结构化特征写入测试记录 JSON。`screening_model.py` 使用这些特征以及后来取得的临床标签，为每个病种分别训练逻辑回归基线模型。记录的规则版本必须与训练程序一致。本目录的训练代码无需第三方 Python 包（服务端在 `server/`，见其 `SERVER.md`）。

## 记录格式与版本

训练与推理只读取记录中的特征表，口径与 `shared/sync` 的 `RecordSummary` 一致：

| 病种 `kind` | 规则版本（必须完全一致） | 质量合格条件 | 特征位置 |
|---|---|---|---|
| `DRY_EYE` | 顶层 `assessmentVersion = dryeye-9.18-rules-1` | 顶层 `valid == true` | 顶层 `features` |
| `PRESBYOPIA` | `assessment.modelVersion = protocol-9.18-rules-1` | `assessment.quality` 存在且不是“不足” | `assessment.features` |
| `STRABISMUS` | `assessment.modelVersion = protocol-9.18-rules-1` | 同上 | `assessment.features` |

特征键与顺序照搬 `DryEyeProtocol.kt`（`DryEyeAssessment.evaluate`）与 `ScreeningAssessment.kt`（`ScreeningAssessmentModel`）中的 `features` 映射，定义在脚本的 `FEATURES`。记录缺任何一个键都会被拒绝（说明 App 与训练程序版本已错开）；值为 `null`、非有限数或布尔值时按缺失处理并显式编码。App 改动特征或阈值时须同时升规则版本常量，并同步脚本的 `INPUT_VERSIONS`／`FEATURES`；旧版 `research-rules-2` 记录与旧模型不再接受。

## 当前风险分级规则

分级是在数据质量合格后才执行的**原型工程规则**。资料支持综合观察这些测试项目，但下述数字切点尚未经过本设备或临床队列验证，不是文献给出的通用诊断界值。

| 病种 | 质量不足（输出“无法评估”） | 中风险触发 | 高风险触发 | 低风险含义 |
|---|---|---|---|---|
| 干眼 | 测试未完成；自然眨眼阶段有效视标 <10 题或睁眼阶段 <4 题；双眼可见有效帧 <80%；约 40 cm 距离内时间 <70%；头部明显偏转时间 >30%，任一即是 | 以下异常项至少一项：自然眨眼频率不在 10–16 次/分钟；最长持续睁眼 <10 秒；视觉维持率 VMR <0.85；睁眼阶段视标较起始放大 ≥2 档 | 异常项 ≥3；或异常项 ≥2 且症状频率为“经常／几乎总是” | 四项均未触发；不能排除干眼。接近临界时提示复测 |
| 老视 | 任一眼别（右／左／双眼）近视力 <4 题；有效移近法测量 <2 次；近点重复差异（MAD）>5 cm；远近切换数据不足或缺近／远任一距离；多距离视力有效距离 <2 个；缺年龄 | 调节幅度低于 Hofstetter 最小值（15 − 0.25×年龄）；或 40 cm 任一眼别近视力 <0.5；或 1 分钟远近切换完整循环 <3 次，三者之一 | 年龄 <45 岁且调节幅度 <5 D（较早老视样下降）；或调节幅度低于同龄最小值且有眼别近视力 <0.5 | 完整测试中均未触发；不能排除老视。日常矫正模式只评估当前矫正条件下的近距离表现，不解释为残余调节能力 |
| 斜视 | 注视校准／追踪质量检查未通过；可测阶段有效帧率 <50%；注视任务有效帧 <20 或连续 <3 秒；解除遮盖后可用事件 <2 次；无法计算双眼对称性指数 BSI | 遮盖解除后再注视中位偏移 ≥6Δ；或 BSI <0.5 | 注视稳定（水平标准差 ≤5Δ 且垂直 ≤2.5Δ）且水平偏斜 ≥10Δ 或垂直偏斜 ≥5Δ | 均未触发（App 显示“未见异常”）；不能排除间歇性、小角度或垂直斜视 |

斜视棱镜度为估算值：以平均角膜直径 11.7 mm 作像素尺度、按 Hirschberg 15Δ/mm 换算，未针对本机标定；BSI = 0.5·r_h + 0.3·r_v + 0.2·(1 − d_norm)。屏幕白点不是经过临床标定的同轴点光源；角膜反光候选、头姿和个体视轴偏心都可能造成假阳性或假阴性。低风险表示“本次未触发预设条件”，不是确诊阴性或经验证的低患病概率。

## 使用真实临床标签训练

准备一个仅含同一病种的会话 JSON 目录（App 导出的原始记录），以及 CSV：

```csv
session,subject_id,label
presbyopia_123.json,P001,1
presbyopia_456.json,P002,0
```

`subject_id` 是脱敏后的受试者标识；同一人的多次测试必须使用同一个值。`label` 为临床方案最终定义的 0/1 金标准，不能填手机端的探索性评估结果。干眼可由泪膜破裂时间、泪液分泌、睑板腺等检查综合定义；老视应由专家明确远用矫正下的调节功能异常或临床老视标签；斜视可由临床遮盖及三棱镜检查定义目标病种。各病种分别准备标签表，不要混用。

```powershell
python -m unittest discover -s backend -p "test_*.py"
python backend/screening_model.py train --kind PRESBYOPIA --sessions data/presbyopia --labels data/presbyopia_labels.csv --out data/presbyopia_model.json
python backend/screening_model.py predict --model data/presbyopia_model.json --session data/presbyopia/presbyopia_123.json
```

干眼、斜视分别用 `--kind DRY_EYE`、`--kind STRABISMUS` 另训模型。程序要求每类至少 5 位受试者，只接受质量合格且版本匹配的会话；按受试者而不是按帧或测试划分留出集（每类约 20%，固定随机种子）。预处理参数仅从训练集估计，缺失值显式编码。输出包含留出集混淆矩阵、敏感度和特异度。这个最小样本限制只为程序能运行，不代表临床验证充分。命令行输出按 UTF-8 写出，避免 Windows GBK 控制台报编码错误；需要阅读时可重定向到文件。

`predict` 会核对模型格式（`eyeproject-screening-logistic-v2`）、输入版本与特征列表，任一不符即要求重新训练。它输出的是**未校准的研究分数**。0.5 只是软件演示切点；手机端低／中／高来自上面的规则，与离线逻辑回归分数无关。在获得足够独立临床样本并确认金标准、患病率、跨设备表现和阈值之前，不把此分数或三级类别作为诊断概率。模型不会自动下发到手机；手机端继续显示透明的规则基线（规则是安全底线，学习模型在取得临床标签前只做影子运行，见 `docs/后端与智能评估设计-2026-10-15.md`）。临床试验阶段应另做受试者级交叉验证、独立外部验证、概率校准、按年龄与设备分层评价，并锁定模型后再评估推广。

## 判读依据与边界

原始需求文档：`docs/智能眼科-整合9.18.docx`，研究内容一至三。文档提出多指标融合、临床标签训练与三棱镜遮盖检查对照，但尚未提供可训练病例、个体设备光源几何标定、经过验证的归一化瞳孔反光阈值或年龄常模。

- [AAO EyeWiki：Presbyopia](https://eyewiki.aao.org/Presbyopia) 指出需结合矫正近视力、屈光状态和近用需求解释表现。
- [主观移近法与客观调节测量的比较](https://pubmed.ncbi.nlm.nih.gov/15210220/) 发现移近法可高估客观调节幅度，因此调节幅度与“调节年龄”只作参考。
- [AAPOS：斜视测量](https://www.aapos.org/glossary/strabismus-measurements) 将角膜反光、遮盖与棱镜检查区分，且说明反光位置可受生理视轴差影响。
- [手机眼位测量初步研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC6369861/) 使用专门的光源和拍摄协议；本项目屏幕白点形成的反光仍待验证。
- [照片 Hirschberg 与三棱镜遮盖比较](https://pubmed.ncbi.nlm.nih.gov/34851974/) 显示两者并不能直接互换，因此手机估算的棱镜度与文档中的 10△、5△、6△切点只作工程门槛。

代码中的眨眼频率 10–16 次/分钟、VMR 0.85、持续睁眼 10 秒、近视力 0.5、调节幅度 5 D、BSI 0.5、10Δ／5Δ／6Δ 等值只为运行工程原型，均需用临床数据重新确定。当前斜视结果不区分内斜、外斜、垂直斜视或隐斜的诊断类别。
